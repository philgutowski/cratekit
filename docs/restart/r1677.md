**R-1677, #813, the integrity check's throwaway copy is measured before the
capture and named when it has no room, built in the cloud lane on
2026-11-13.** Filed at the landing of #804 (R-1665). Large by METHOD: it

**What failed, reproduced on the base.** Since R-1665 `rb_writer.integrity_ok`
never opens the capture: it copies the file set into the system's temporary
directory and checks the copy. Nothing measured that room. A temporary volume
too small for the copy made the check answer False, the capture was recorded
unverified, and the guarded write refused it as `snapshot-integrity-failed`
with the remedy `report-defect`, over a capture nothing was wrong with.
Driven on the base with the temporary directory on a real 256 KiB tmpfs and a
330 KiB file set: exactly that refusal. The rehearsal's own check of its
scratch database in `intake/land_cli.py` refused the same volume as a
database that fails SQLite's integrity check. The tests written first,
`tests/test_snapshot_check_room_r1677.py`, were 24 of 27 red on the base, and
the rehearsal's two red without its change.

**What landed, two layers, guard first.**
1. **Measured before the copy.** `snapshot.assert_room_for_check`, asked by
   `capture` beside `assert_room_for_capture` before anything is created, and
   only when the real check will run (a stand in verifier makes no copy). It
   measures `rb_writer.file_set`, the one list the copy loop now reads, in
   allocated bytes with the capture's headroom, on
   `rb_writer.disposable_root()`, the directory every throwaway copy is made
   in. When that directory shares the store's volume (`_same_volume`, reading
   a store not yet made as its nearest parent's volume, an unreadable device
   counted as shared) the capture's own estimate is added, since both land
   there. Short, it refuses as the new `snapshot-check-temp-full`,
   PRECONDITION, with steps rather than a remedy token as
   `snapshot-store-full` carries: free space there, or set `TMPDIR`. No
   temporary directory at all, or one whose free space cannot be read,
   refuses the same way.
2. **Named when it still happens.** `integrity_ok(..., raise_copy_failure=True)`
   raises `IntegrityCheckCopyFailed` for the copy alone; an open refused, a
   consistency check not ok, or any error after the copy stays the check's
   False. `capture` asks for it, and `check_had_no_room` reads only no space
   and a reached quota as no room: the manifest is rewritten unverified
   (`_record_unverified`, shared with U272's flush refusal) and the capture
   refused under the room slug. Any other copy failure stays an unverified
   capture, as before. Every other caller of `integrity_ok` keeps its False.

The class one file over, `intake land --rehearse`: its check of the area's
database gets the same two layers.

**Never, and driven.** A capture recorded verified without a completed check,
or a real integrity failure told as a room message: round one drove five
producers of the first and three of the second, none produces either, and the
mutation table's `K3` and `L3` rows (another copy failure recorded verified,
or reported sound) are killed.

**Unchanged:** what is copied and checked (R-1665), the flush and its order
(U272), where the throwaway lives, every existing refusal. **Decided here,
recorded:** the measure runs only when the real check does; the in flight
refusal is limited to no space and a quota, so a permission error is never
told as a full volume; an open that fails after a copy that fit stays a
failed check rather than a room message, the conservative direction, filed
below. The slug is written as a literal at each refusal rather than held in a
module name, which would have put `snapshot.py` in the named at risk
population. Code conventions were the session's to decide.
