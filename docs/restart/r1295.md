**R-1295, #551, `crate organize` reads each downloaded set row by row, so one
track the account lists with no title or no artist never keeps a set out of
INSPIRATION, built in the cloud lane on 2026-11-05.** A medium card: it
changes what `crate organize`'s `inspiration` step writes, since a set filed
unread whole now gets its playlist.

**What the defect was.** `organize/inspiration.py` `_read` listed a set
through `label_cli.playlist_listing_or_refuse` and read the rows whole with
`match.read_tidal_tracks`, which raised `UnreadableList` when one row named no
title or no artist. `plan` filed the whole set unread with the reader's
message, so none of its readable tracks was matched and no INSPIRATION
playlist was written. Driven first on `main` by this unit's own tests
(`64af906b`): four of the six failed, each set filed unread.

**What landed.**

- `_read` reads each row alone with `match.read_row`, keeping its place in the
  set. A row the reader refuses is set aside through `intake_cli.set_aside`,
  the reader's own rule for which half is absent, extracted from
  `list_playlist_readable` (which calls it and reads as before), so the sweep,
  the pair and INSPIRATION say one word.
- Each unread track is a miss at its place in the set, named by artist and
  title as the account lists them (`no artist` or `no title` where blank), its
  id and why, merged with the set's other misses in set order. The readable
  tracks are matched as ever, and the digest covers the unread misses through
  the miss lines.
- `SetRow.unread` keeps them beside `wanted` (now each track with its place),
  so `again` decides the write from exactly what the plan read.
- A set no row of which reads is shown unread, never as a set with no match,
  naming the first five tracks (`NAMED_UNREAD`), counting the rest, and saying
  how many tracks the provider withheld.
- `docs/GUIDE.md`, under `crate organize`.

**Decided, not asked (code).** A refused row with no provider id still files
its set unread, as the brief asks, with the engine's message and a clause
saying the missing id is what held it back. A row the reader reads is matched
with or without an id, as on `main`: INSPIRATION keys nothing by provider id,
so refusing it as the intake's queue must would leave out sets written today
(pinned by `test_a_readable_track_with_no_provider_id_is_matched_as_before`).
No new warning: an unread track inside a written set is a miss on the gate
like any other, as the mirror's downloads name one (R-1289), and the set level
`organize-inspiration-unread` warning still covers a set filed unread.
