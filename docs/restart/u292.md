**The verb.** `crate tag backlog [--catalogue]`
(`tagging/backlog.py`, `tagging/backlog_cli.py`, a `tag.backlog` registry
entry on doctor's diagnostic surface, so a person reads it as check rows, the
way `report genres` is read). On one handle opened to read, it walks
adoption's census and takes every `needs-genre` row, then reads each verb's
own plan over the same handle. Each row lands in exactly one cause:
- `row-lags-file`: the file carries a genre adoption files by. Served when
  `rows.plan_rows` would write it, else left with that verb's reason.
- `no-genre`: weighed by `suggest.plan_suggestions` at the floor.
- `too-coarse`: `tag retag`'s, named and not planned.
- `off-taxonomy`: grouped by word folded on case, one question each.
- `file-unread`: the file's genre could not be read.

A row whose file is not here is in no cause and is counted apart by why. A
row with no path at all, a streaming row, is left out, since no folder is
ever filled from it. A routed row that `tag rows` would give a word no folder
takes is named as joining, and the projection adds it back.

**The floor and the evidence.** `high`, `tag suggest`'s default band, as a
constant rather than a flag. A lone catalogue match (weight six) passes; two
artist neighbours do not. Each proposal carries its genre, band and share of
the weighted votes. Its source is the catalogue whose match voted for that
genre, with the catalogue's own word, or `neighbours`. With `--catalogue` the
backlog asks what `tag suggest --catalogue` asks: Discogs, Beatport when
Discogs gives no genre, then Deezer by ISRC. It goes through that verb's
paced lookup, its stop after three unread rows and its week long kept
answers, so `tag suggest --catalogue` reads the same answers and asks nothing
again.

**The words.** Each word's answers are planned by the two verbs' own edits on
the active copy, `taxonomy_word.alias` and `taxonomy_word.folder`, so only an
answer those verbs take is offered:
- an alias of the heaviest neighbour genre at medium or better;
- its own folder;
- leaving it for hand tagging.

Its own folder is recommended when it would file 50 rows or more (`report
genres`' threshold). Otherwise the alias is recommended when it moves a row,
otherwise leaving it. What an answer moves is counted by the row:
- a folder files a row whose row carries the spelling exactly, or whose file
  does and `tag rows` would write it there;
- an alias retags each file holding the word alone (said as files), and its
  rows follow only where the library has a genre entry for the alias's genre
  (said as rows).

A word already saved as an alias, or another case of a folder's name, is
`settled`: its one command plans no change to the copy and retags its files.
A word both edits refuse is named with the refusal's words and step.

**The report.** Check rows give:
- the causes and the proposals;
- each word with its question, its answers, the recommendation first, and
  each answer's command;
- the campaign as the existing verbs in order, with the rows each moves;
- the remainder by cause and reason with what settles it;
- the excluded and joining rows;
- needs genre now, after the campaign with no word answered, and with every
  word given its widest answer.

The summary carries every row, word and count, and a digest over them that
names no copy.
