**R-1432, #630, a finish of a stopped order puts an unread track where the
stopped write was taking it, not where its interrupted move left it, built in
the cloud lane on 2026-11-07.** A large card: it changes the order `crate sync
pair` writes on the account at a finish. Filed by R-1418's build (#618,
`r1418-a`): at a finish the plan read every readable track as the stopped
write would have left it, but `_with_unread_placed` put an unread track
(R-1264) back behind the track the listing showed before it, which is where
the interrupted move left it, so a stopped move of a track the provider
cannot read was made permanent and reported finished.

**What landed.**

- **The stopped write's target places an unread track at a finish**
  (`_with_unread_placed` in `sync/pair_cli.py`). It takes an optional
  `target`: each unread id the target names that the account still lists
  is placed first, in the target's order, behind the nearest track the
  target puts before it that the order holds, or the front when none; an id
  the target does not name, one listed since the stop, keeps R-1264's rule,
  behind the track listed before it; an id of the target the account no
  longer lists is never put back. `plan_pair` passes the target only when
  the plan finishes a stopped order (`stopped is not None`, the account on
  the stopped write's path); a person's move that takes the account off the
  path, and every plan with no stopped write, pass nothing.
- **The gate says so** (the review's two rounds). The pair's facts line and
  the `sync-pair-unread` warning said an unread track stays where it is on
  both sides; on a finishing plan that asks an order each now adds that the
  order puts each where the stopped order was taking it, or else behind the
  track it follows. The module docstring says the same.
- No refusal, check or guard changes: `expect`, `agreed` (still the plan's
  reading, `account_before`), the adapter's membership and agreed order
  checks and the stale check are untouched, and the digest changes only
  where the order it asks changes.
