**U965, #1084, the menu bar app's Swift package, built, tested and bundled
on GitHub's macOS runners, built in the cloud lane on 2026-11-25.** The first
Swift card of the menu bar app (idea #377, decision 1: the cloud writes the
Swift and GitHub's macOS runners compile, test and bundle it). A medium card:
it writes nothing to a library, a database or the account.

**What landed.**

- **`app/`, a SwiftPM package**, no Xcode project, tools 5.9 (Swift 5
  language mode), macOS 13 the floor. `CrateEngine`, Foundation only:
  `Envelope.swift` decodes the version 1 envelope `cli/output.py` emits, its
  required keys with nullable values held as required (an absent key is
  malformed, null is none), a cause with its chained `inner`, remediation and
  `shown`, a pending human action, an outcome this app does not know kept as
  `unknown`, and a frame of another version refused by name; `JSONValue.swift`
  holds a verb's `data` and a cause's `detail` whole; `CrateSetup.swift` reads
  the path in the `cratePath` default as unset, not absolute, missing, a
  folder, not executable or ready; `CrateRunner.swift` starts crate by that
  absolute path with no shell, `--output json` then the verb's arguments, a
  minimal environment (`HOME`, `LANG` and the `LC_` locale keys, `TMPDIR`, and
  `PATH` of crate's own directory then the system directories), standard
  input from the null device, both pipes read as they fill, and a timeout that
  sends SIGTERM, then SIGKILL after a three second grace. Every result is a
  value: an envelope (a refusal included, with its exit status and standard
  error), a setup state, timed out, signalled with its number, undecodable
  with its first 256 bytes (empty output named as such), launch failed.
  `CratekitBar` is the `MenuBarExtra` with one line of the setup state and
  Quit, accessory activation so no Dock icon. `CrateEngineTests`, 30 XCTests.
- **`app/scripts/bundle.sh`** builds the release product, assembles
  `build/CratekitBar.app` with `Bundle/Info.plist` (`LSUIElement` true), signs
  it ad hoc with `codesign --sign -` (decision 2: no Apple account), verifies
  the signature, and zips it with `ditto` so the executable bit and the
  signature survive an artifact upload.
- **`.github/workflows/app.yml`** on `macos-15`, triggered on push and pull
  request only by `app/**`, `tests/test_app_fixtures.py` and itself: `swift
  build`, `swift test`, the bundle script, the zip uploaded for seven days.
  `ci.yml` is untouched. The repository is public, so the macOS minutes cost
  nothing.
- **`tests/test_app_fixtures.py`** drives doctor on the synthetic green
  machine, `profile set slim` stopping at its gate with `cause.detail.shown`,
  and `audit coverage` over an export without the governed tree (a refusal
  with two steps) through the real dispatcher, validates each envelope, puts
  the run id, the times and the temporary roots in fixed form, and compares
  the text with `app/Tests/CrateEngineTests/Fixtures/*.json`; `REGEN=1`
  rewrites them, the convention `tests/golden/` uses. Every value that would
  differ by machine comes from the synthetic doctor probes; review round one
  varied the time zone, the locale, the clock, xdist, Python 3.13 and
  `sys.platform` and the text held, and ran the real `crate` the way the app
  does (no shell, no terminal, the minimal environment) to the same gate
  fixture.

**Decisions, recorded.** The fixtures are read beside the test file by
`#filePath` and excluded from the target, rather than a resource bundle, so
the Python test writes plain files the Swift test reads. The doctor fixture
is the green machine's, so it is stable across hosts and shows thirty
passing checks; a failing doctor is a refusal shape the gate and steps
fixtures already carry. The bundle is the runner's architecture alone, arm64;
a universal binary is left for the install card if Phillip's Mac needs it.
The runner is synchronous with an async wrapper, so a later card calls it
from a task.
