**R-1385, #600, one `crate sync pair` command queues a track no landing
brought in once for each pair listing it, and again beside another pair's
job still holding it, built in the cloud lane on 2026-11-07.** A medium card:
it changes what a sync pair queues for download, through one planner and its
apply time check, with no new verb or store. Filed by U229's landing (#593):
a pair read only its own jobs as holding a track, so two pairs listing one
track the library lacks each queued a job for it, and a pair listing a track
another pair's job still held queued it again.

**What landed.**

- **Every pair's jobs read once per plan.** `_Reader.held_by_jobs` in
  `src/cratekit/sync/pair_cli.py` maps each remote id to the source account
  and playlist name of every `sync pair` intake job that did not fail or
  cancel, newest first, read from the jobs `pair_jobs` already lists.
  `_queued`, a pair's own jobs, now reads the same map by source.
- **What this plan asked, kept.** `_Reader.asked` holds each remote id a pair
  of this plan asks to acquire, with the pair that asked, so a later pair of
  the same command does not ask again.
- **Asked in order.** `plan_pair` asks, for each lacking track, the pair's
  own jobs (awaiting, as before), the twin's hold (U221, on hold, so a plain
  pair listing a twin's held track leaves the twin's choice where it was),
  then `_queued_elsewhere`, another pair's job ("queued for" its playlist) or
  an earlier pair of this plan ("to be queued by this sync for" it), both
  named awaiting with that reason, and only then acquires.
- **The warning says which.** `_warnings` splits the awaiting rows: what a
  job holds, by an earlier sync or for another pair, and what another pair of
  this sync queues once its rekordbox side is applied, so a skipped first
  pair never reads as a queued track.
- **The apply check reads every pair's jobs.** `check()` builds the tracks
  held now from every pair's jobs, so a job another pair's sync queued since
  the plan refuses the write as `decision-stale`.
- The digest is untouched: `acquire` is in it and `awaiting` is not.
- `docs/GUIDE.md` says a track the library lacks is queued once, however many
  pairs list it.
