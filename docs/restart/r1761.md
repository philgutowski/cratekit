**R-1761, #893, a backup refuses a library root it cannot prove is the
library, built in the cloud lane on 2026-11-21.** Filed by U317 (#877) from
its round two review, which drove an unmounted tmpfs volume and watched a full
check move 12 of 12 mirror files into the dated archive and reset the files
age. Large: it changes the path that moves and archives mirror files.

**The defect, driven first.** On the base, with a real rclone between local
folders, an empty folder left at the root after a completed backup was walked
as a library with no files, and both a quick run and `--check` moved all 12
mirror files into the archive. The test file
`tests/test_backup_unproven_root.py` was committed before the fix.

**What proves the root**, decided at the plan and failing closed. In
`modules/tools/backup.py`'s `_plan_files`, before any command exists, so a
refusal removes no record, strikes no token, keeps no census and publishes no
files age:
- **The identity.** `_not_the_recorded_volume` reads the volume gate
  destructive sessions pass (`session.assert_volume_identity`). A recorded
  identity read and not the root's refuses `library-root-foreign`. An
  identity the platform cannot read, every Linux volume, or none recorded, is
  left to the second proof, as is a read that raises.
- **The content, against a census.** `backup_census.json`, new installation
  state (`core/config.py`), keeps how many files outside the library's own
  state folder the last completed files portion walked, for this root and
  mirror, and no run removes it before it sends. `_unproven` and `_history`
  refuse `library-root-unproven` for a root holding no file at all, one
  holding none outside its state folder while the census, or failing it the
  record or the library's own files fact, says a backup held some, or one
  holding under a tenth of the census (`backup_record.LIBRARY_FLOOR`). A
  damaged census counts as a backup having happened.
- **A root of only its state folder** that passes (a new library, or one the
  last backup found empty) is mirrored with rclone's `--max-delete 0`, which
  counts a move into the archive as a delete, so a mirror holding files it
  lacks fails the run rather than lose them. A skip and a quick run of it are
  planned as any other.
- **A walk that refused** is counted by `backup_record.probe`, so the floor and
  the census keep a number.
- **At run time**, just before `rclone sync`, `backup_record.root_still_holds`
  holds the root to the device the plan read and, where the plan found the
  library's files, to one still being there.
- **`--library-emptied`**, frozen in the queued payload and rebuilt on
  resume, passes the content proof only at a root still carrying the
  library's own files fact, and never the identity. `--check` and `--full`
  are no override.

**Decided by the session, recorded here.**
- **What proves the root**: the identity where read, then the census, then the
  record, then the files fact; a census rather than a marker file, since a
  marker on the volume goes with the volume and proves nothing at a mount
  point, and a remote listing would be an rclone command before the refusal.
- **An unread or unrecorded identity is left to the census** rather than
  refused, since every Linux volume reads none and refusing would stop every
  backup there.
- **The floor of a tenth**, so a stray file at a mount point refuses while a
  person who removed most of a library is backed up (the archive keeps what
  went).
- **A root holding nothing at all always refuses**, with no history needed:
  no library Cratekit set up looks like that, since setup writes its state
  folder.
- **The flag's name**, `--library-emptied`, and that `--check` is no override.
