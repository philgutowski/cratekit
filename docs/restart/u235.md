**The cause, found and reproduced.** Not a neighbour. The test's job queue
and run records sit under the conftest's state roots, a fresh `mktemp` per
test, so no other test's job can reach it. Measured: 200 runs of the test
alone and ten runs of its whole file (710 tests) under `-n 3` all passed.
What it depends on is the clock and a short random tail.
`cli.output.new_run_id` minted every run identifier and, through
`jobs.enqueue`, every job identifier, as a whole second's stamp and
`secrets.token_hex(2)`, sixteen bits. The test mints 14 identifiers inside
about 1.7 seconds. A scratch plugin outside the tree forced each of the 91
pairs of those 14 draws equal, one run each:

- pair (0, 3), the first `sync all`'s run against the new pass's: failed at
  line 1115, `assert '...Z-d112' != '...Z-d112'`, the card's
  `pass_run != earlier["run_id"]`;
- 13 pairs of job identifiers: failed with `IntegrityError: UNIQUE constraint
  failed: jobs.job_id` at enqueue;
- the other 77 passed.

So at sixteen bits about 14 runs in 65,536 failed, roughly one in 4,700,
which is the one sighting the card records. R-22 is this defect, recorded
2026-08-03 with three later sightings in other tests, two of them the same
duplicate job id.

**What landed.**

- **`new_run_id`'s tail is sixty four bits**, `secrets.token_hex(8)`, the
  width `snapshot.new_stamp` already carries, with the docstring saying why.
  The stamp before it is unchanged, colons included, so an identifier on disk
  from before reads, sorts and names a file as a new one does: `gates.run_path`,
  `held_plan`'s step files, `intake.land_cli.default_name` (colons taken out),
  `organize.mirror_frozen`'s bound of 128 characters. `intake.shelve`'s four
  character pattern reads only batch names from before U110, which no new
  identifier becomes, and is left as it is.
- **Tests, the failing ones first** (`3550d276`, both red on the base):
  `tests/test_cli_contract.py`, two thousand identifiers minted at one frozen
  instant are all distinct (near certain to collide at sixteen bits, about
  one in eight at twenty four, about once in 10^13 at sixty four), and the
  tail is a literal sixteen hex characters, the shape `tests/test_snapshot.py`
  pins for the capture stamp.
- **The card's three scenarios.** The test under repeat: 200 of 200 under
  `-n auto` after the fix, with a scratch repeat plugin (the venv has no
  repeat plugin, and none was added). Two runs created inside one second: the
  frozen instant test. A queue holding another test's job: measured
  impossible, the store is per test; no test added.
