**U266, #695, `crate setbuild`'s first index opens each file once, not seven
times, built in the cloud lane on 2026-11-12.** Filed from the speed survey
of 2026-11-12. Built on the suite's synthetic containers only; the wall time
on the real library is owed (below).

**The change.** `setbuilder.read_index_tags` reads the seven `INDEX_FIELDS`
through one `tags.read_tags(path, INDEX_FIELDS)` open, where it asked
`tags.read_tag` once per field and each call opened the file again. It is the
shared one open reader R-666 added for the match index and U250 (#679) reused
for the derivations; no second reader was written. The docstring now says
what the function does. `build_index`, the cache key, `CACHE_VERSION`, the
template stamp and the rule that a read holding no field is never cached are
untouched, so the warm index is trusted exactly when it was.

**Why the answer cannot move.** `tags.read_tag(path, field)` is defined as
`read_tags(path, (field,))[field]`, so the seven call reader and the one call
reader run the same lenient body: an absent field, an undecodable field (its
neighbours still read), a container the tag module refuses (nothing opened)
and a file mutagen cannot open or does not recognise all read None, and
nothing raises. The keys come back in `INDEX_FIELDS` order as before. The one
behaviour that moved, found by the review, moved for the better: an I/O error
or a retag between two of the seven opens could give a partial or torn
reading, and one open cannot. That removes the producer R-623 named (a
partial read cached under an unchanged identity); its other half, reporting a
failed read as a failure so the index can decline to cache it, stays open,
since the brief keeps what the cache refuses to store unchanged.

**The proof, by count and by equality, no clock.**
`tests/test_setbuilder_one_open.py`, written first and red on the count before
the change (46 failed, seven opens where one is asked): with `mutagen.File`
wrapped, one `read_index_tags` is exactly one call on eight containers (FLAC,
AIFF under both suffixes, WAV, MP3, M4A, Ogg, Opus) under six tag shapes (every
field, a lossy marked head, two fields, padded, beyond ASCII, untagged), each
mapping equal in value and key order to the seven single field reads that were
the function's body, and the every field shape pinned literally on every
container. An undecodable MP4 field reads None and its neighbours still read;
an unopenable, an empty, an unrecognised and a vanished file read all absent
in one open and never raise; every suffix `iter_audio` offers that the tag
module refuses opens nothing, and that list is derived from `AUDIO_EXTS` and
proven to split the way the tag module does. A cold `build_index` over a
mixed library of 28 files makes one open each, builds the same index and
writes the same cache as the seven open reader; the warm walk answers the
same index and opens only the files whose read held no field, the cache's
refusal by design. One verb level test in `tests/test_setbuilder_cli.py`
counts opens through `crate setbuild`: each library file once cold, none
warm, the warm answer equal to the cold. A convention of the session's: a
dedicated test file, as U250 did, rather than another block in the long
`tests/modules/test_tools.py`.
