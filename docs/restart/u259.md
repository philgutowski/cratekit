**U259, #688, `crate analyze check` reads the collection in a handful of
statements, not one or three a row, built in the cloud lane on 2026-11-12.**
Filed from the speed survey of `main` at `a7fcc9f4`: when INBOX / Analyze held
no row, `_unanalysed` walked every collection row and asked for that same row
again by its ID, and `read_row` asked twice more for each row in scope, once
through `analyzed.member` and once for the key, title head and analysis path,
so a ten thousand track library cost tens of thousands of point reads.

**What landed.** `intake/analyzed.py`: `member(db, content_id)` is now its read
by ID and a call of `judge(content_id, row)`, which holds every line of the
judgment it held (a missing row, the removal marker read through
`rb_writer.soft_deleted` with its refusal, `Analysed`, `AnalysisDataPath`).
One rule, two entries; the clear still calls `member` and is otherwise
untouched. `analysis/rekordbox_check.py`: `_unanalysed` judges each row the
one collection read hands over and returns the waiting rows by ID with the
rows themselves, which `Scope.read` carries (left out of equality and repr);
`check_rows` reads every row in scope it does not already hold 500 IDs to a
statement (`_content_rows`, the form `write/row_defaults.read_mapped` uses),
judges the rows in the scope's order, and returns the `Check` with the scope's
rows dropped, since they belong to the copy's session; `read_row` takes the
row in hand through `content`, reading by ID once only when handed none. A
batch the binding cannot load (a later row's date it cannot parse) is read a
row at a time by ID instead, so the first failure in the scope's order is
the answer as before; a collection row whose ID is stored as bytes stays out
of the scope of every row not analysed, as the read by ID always left it.

**Why the answer cannot move, and what proves it.** The check reads the
private copy `read_only_copy` makes, so nothing changes a row between the
read and the judgment, and before U259 the second read by ID inside
`_unanalysed` returned the identity mapped object the first read built. The
proof is driven, not argued: `tests/test_analyze_check.py` keeps a verbatim
copy of the per row reads as the reference, and the verb's whole answer (the
exit code, outcome, data and its digest, warnings, cause and pending action,
less the run id) equals it on a mixed library of nine kinds of row in the
INBOX / Analyze scope, the scope of every row and a named landing, on two
rows whose removal marker cannot be read (the first in order refuses), on a
row the binding cannot load after one that refuses, on an ID stored as bytes,
on IDs stored as integers in both scopes, and on a 1,015 row scope of three
chunks with a removed, a deleted and an analysed row past the first.
