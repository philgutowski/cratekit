**U206 built, 2026-11-05, in the cloud lane on `cloud/496-isrc-cache`, issue
#496: an ISRC the provider already answered is not asked again, so a rehearsal
and its live run pay for their lookups once.** Filed from the attended sitting
that ran `crate sync pair` live for A83, where the rehearsal's ISRC matches were
thrown away with the copy's state and the live run asked every one again.

One new module, `acquire/isrc_cache.py`, owns the cache: one JSON file of the
installation, `isrc_cache.json`, beside `provider_gate.json`, with a sibling
lock, both declared in `config.STATE_FILES` as installation state that is never
restored. It is read and written at exactly two seams, the outbound account's
`match_track` (through `_isrc_tracks`) and the catalogue's `tracks_for_isrc`, so
no caller above them knows it exists and `sync pair`'s links and remembered
misses sit above it unchanged. Entries are keyed by the folded ISRC and the
client's country code. A remembered track is a small frozen object carrying
what the callers read (identifier, title, version, lead and billed artists by
name, album name, availability, ISRC); a real client track built offline reads
the same through `match.read_row`, `_agrees`, `_streamable`, `_album_name` and
`_artist_names`, streamable and withdrawn, and the review drove seven more
shapes over sixteen row spellings.

Only an answer is kept: a track list, or a not found the client said in so
many words, which `isrc_cache.said_not_found` decides for both seams (the
client's own `ObjectNotFound` by exact name, or a 404 status). An outage, a
rejected session, a rate limit, an `InvalidISRC` (which the account still reads
as no match, R-477, unchanged) and any other class named for a not found are
never kept. Nor is an answer holding a track with no identifier or no artist or
title, the rule `sync pair` and the mirror already keep one layer up (R-988,
U198), nor a spelling that is not its own fold. A found answer is reused for
`[provider] isrc_cache_days` days, 30 unless set, validated as a whole number
zero or more; a not found for 7, or the setting when shorter; 0 turns the cache
off. An expired entry, or one stamped later than now, is asked again and
replaced. Writes take the lock, re-read, merge the one entry, drop expired
ones and replace the file atomically; a lock not had in five seconds skips the
write; a file that does not parse is renamed aside and rebuilt; a file that
cannot be opened answers nothing. No verb is refused over the cache.

Every run that looked an ISRC up carries an `isrc-lookups` warning, "N ISRC
lookups answered from the cache, M asked of the streaming provider", read off
the module through `sys.modules` so the dispatcher imports nothing new. Doctor
gains `provider.isrc-cache`, an INFO note with the count kept, whether the file
does not parse or cannot be read, and every file set aside.
