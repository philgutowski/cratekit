**U232, #606, the test suite reads the same whether or not rekordbox is
running on the Mac, built in the cloud lane on 2026-11-07.** A small card:
test infrastructure only, no file under `src` changes. Filed when the v0.13.0
cut was refused on a red Mac battery because rekordbox was open on the
machine and two tests read the host's real process table.

**What landed.**

- **Every test reads the host as a machine with no rekordbox**
  (`tests/conftest.py`, `_no_host_process_table`, autouse, on its own
  MonkeyPatch instance like the others). Both routes to the process table
  are answered: `core.processes._platform`, the careful scan's seam, answers
  an empty table, and pyrekordbox's `utils.get_process_id` answers no
  process (zero, or pyrekordbox's own `RuntimeError` under `raise_exec`).
  The second covers `get_rekordbox_pid`, `get_rekordbox_agent_pid` and the
  binding's own bound `db6.database.get_rekordbox_pid`, asked at
  construction and inside `commit`, which was the named sync pair test's
  exit 1: it faked the utils name and the binding still walked the host.
- **A tripwire beneath both.** `psutil.process_iter` and `psutil.pids` refuse
  and record, and the fixture fails the test at teardown over anything
  recorded, since the careful scan turns any exception into a refusal of its
  own and a refusal alone would be swallowed.
- **The opt in is a marker by name**, `real_process_table`, registered in
  conftest. `test_process_scan.py`'s test that the unreplaced seam is psutil
  carries it, and its `real_probes` fixture, which drives pyrekordbox's walk
  over a fake `process_iter`, puts the real walk back.
- **A fake host** (`tests/_host_processes.py`): the real listing plus a
  `rekordbox` and a `rekordboxAgent` at psutil's own `pids`, `Process` and
  `process_iter`, beneath every stub. A fixture, `rekordbox_on_the_host`,
  and a plugin, `pytest -p tests._host_processes`, which runs the whole
  suite as a Mac with rekordbox open would. The learning is
  `docs/solutions/workflow-issues/pyrekordbox-binds-its-own-process-probe-so-a-test-that-fakes-the-utils-name-still-reads-the-host.md`.

**Decided, recorded here.** Questions of structure, decided by the session:
the default is an empty table rather than the host's table filtered, so no
test reads the host at all; pyrekordbox is stubbed at `get_process_id`, the
one name all three of its routes meet, rather than at each bound name; the
opt in is a marker, as `real_pink_read` is; the siblings call the named
tests' bodies rather than parametrizing them, so the named node ids stay as
the brief and any known failures list carries them.
