**U956, #1020, adopt apply leaves out a row whose file is outside the library
root, built in the cloud lane on 2026-11-23.** Filed from attended sitting 104
(A208), where `adopt apply`, rehearsed on a copy of the library, failed
`adopt-entries-failed` on 8 of rekordbox's own sampler preset WAVs, recorded
under two home folders and made readable by the Sampler path mappings of
sitting 101. A large card, since it changes which rows an adoption writes to
playlists: high effort, two review rounds, the full mutation table.

**The mechanism.** The census resolved a sampler row through its prefix rule to
a file outside `library.root` and routed it; the membership write could not
place it (one row alone fails, since its resolved path does not resolve back
through the rule, and two rows on one file are ambiguous besides), so
`_refuse_unplaced` failed the whole pass and nothing was recorded as adopted.

**What landed.**

- **`src/cratekit/adopt/scan.py`**: a new `Readability.OUTSIDE_ROOT`
  (`outside-root`). `scan_rows` reads a row whose resolved path, under the root
  or remapped by a prefix rule, lies outside the root as `outside-root`,
  `excluded`, never probed, its path kept so it can be named. Containment is
  `within_root`: by name on whole components with both sides NFC normalised and
  their dots read, then each parent asked whether it is the root
  (`os.path.samefile`), for a volume that folds case or an alias. A keyword
  `confine_to_root=True`; the tag verbs' walk (`tagging.rows.scanned`) passes
  False, so `tag rows`, `tag suggest`, `tag backlog`, `tag set` and `tag second`
  read such a row as before (the sampler rows' genre is out of scope).
- **`src/cratekit/adopt/plan.py`**: `AdoptionPlan.outside_root()`, the plan
  document's `outside_root` list (content id, recorded location, resolved
  path) and the digest covering it, so the screen and the digest cannot
  differ. **`apply_cli.py`**: `outside_root` joins the gate's facts, so
  `adopt.apply.approve` names each row left out, structured and printed.
  `adopt move`, the genre moves, `organize` and a native landing's filing read
  the same census. A row inside the root that cannot be placed still fails the
  pass, all or nothing.
- **Tool text the census made untrue, corrected in the review rounds**:
  `tag set` names a written row whose file is outside the root as one neither
  adoption verb files or moves, counts only the rows whose file took the genre,
  and names `adopt apply` only when a written row is inside the root;
  `tag second`'s next step excepts such a track; `tag backlog` says a joining
  row's genre takes a folder today rather than that adoption files it.
- **`tests/test_adopt_outside_root.py`**, 26 tests: the containment cases
  (sibling prefix, dots, composition forms both ways, an alias with a gone
  folder under it), the census, the plan and its digest, the sitting's shape
  end to end through the worker (written first and failing on the base with
  `adopt-entries-failed`), the gate structured and printed, a row inside the
  root with two live rows still failing the pass, `adopt move`'s plan, `adopt
  scan`'s counts and artifacts, and `tag set`'s message.
  **`tests/adopt_fixtures.py`**: a `Track` may record a folder of its own.
  **`tests/ratchets/reserved_causes/adopt.py`**: `outside-root` pinned in
  `adopt/scan.py`.
