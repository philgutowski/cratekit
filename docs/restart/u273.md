**U273, #702, the cloud battery keeps its temporary files in one named place,
memory or disk, built in the cloud lane on 2026-11-13.** Filed 2026-11-12
from the speed survey of `main` as an idea; Phillip answered on 2026-11-13
with option 1: the memory filesystem for baseline and compare alike, the
tests that need a real disk named in a short list the battery runs a second
time on disk. Two scripts and their tests; nothing under `src`, nothing in
`pyproject.toml` or the conftest, so the macOS battery is unchanged.

**What landed.**
- **The place** (`scripts/cloud_battery.py`). `baseline` and `compare` take
  `--temp memory|disk`. Each run gets a fresh directory in its place as
  `TMPDIR`, removed when the run ends. Memory is `/dev/shm`, accepted only
  when the mount table reads it as a memory filesystem with 6 GiB free (a
  small `/dev/shm` filled partway would fail tests for want of space, and a
  baseline failure is subtracted unread); disk is the temporary directory the
  battery was given, refused when that is itself on a memory filesystem. The
  header reads `# commit C host H temp <place> history full ids whole`, then
  the summary, then `# on disk test <id>` per listed test and `# on disk
  summary <line>`. `compare` runs in the baseline's place, refuses a `--temp`
  naming the other and a place the machine cannot give now, and refuses a
  baseline naming no place, every one before U273, with the command that
  measures it again. Every place a run needs is checked before the suite
  starts, the disk for the rerun included.
- **The on disk list.** `ON_DISK` names one test,
  `tests/test_repair_rows.py::test_an_id_above_the_bound_that_is_the_files_inode_is_not_random`.
  In memory the whole suite runs, it included, then the list runs again on
  disk and its outcome there replaces its memory outcome. The rerun is
  refused unless exactly the listed tests ran (the reporting plugin now also
  lists passed ids); a collection error of a listed file is read as its
  failure.
- **The driver** (`scripts/mutate.py`), the minimum. `--known-failures`
  reads the place and the on disk list from the same header into a
  `KnownFailures` set that carries them, and refuses a header naming no place.
  Every child keeps its temporary files in a fresh directory in that place,
  and after a run in memory the listed tests that run collected run again on
  disk, their outcome standing. The place module is the battery's own, loaded
  by path, so memory and disk mean one thing in both. With no known failures
  file nothing changes. The table names the place.

**Decided here: the default is disk, and a question waits on the card.**
Measured on the container, the one listed test cannot pass on disk alone: a
fresh file under `/tmp` gets an inode near 620,000 and the test needs one
above 2,000,000. It failed alone on disk 4 of 4 times and with its whole
file; it passed in all three full disk runs below and in the base baseline,
because a full run has written gigabytes by then. So a memory baseline reads
it as the machine's, a test newly read as known, which nobody may trade for
speed without Phillip. `baseline` therefore runs on disk unless `--temp
memory` is named, and METHOD, DEVELOPING and the cloud-unit skill say memory
is not for a merge battery until he answers. The question on #702 offers:
keep disk (recommended, built), make memory the default and accept the test
as the machine's on the container, or change the test so it no longer needs
the volume's own inode counter.
