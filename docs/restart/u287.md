**What landed.**

- **`sync/removed.py`** (new), the plan. A playlist is DOWNLOADED when an
  `intake.playlist` job with a recorded name succeeded and a standing landing
  record of its pass names it by the account's id (U128). SYNCED is every
  downloaded playlist, the sweep cursor's, every playlist an intake job of
  this library was queued for (the cursor as it is in effect, round one), the
  taken record's, one still titled with the retired prefix (round two), the
  pairs, and the account's hearts. A track is removed when its playlist's
  listing holds no row of its id, its ISRC or its folded recording, a
  set aside row included (round one). Each removed report is resolved by the
  backfill's rule and gets one answer: left; kept, held before the pass;
  kept, not this pass's file (outside the `filed_batch` folder its own pass's
  landing recorded); kept, on another synced playlist; kept, in a playlist of
  yours (any live membership but the intake tree, the routing tree when it is
  database native, and the twins a landing recorded for a playlist it left);
  offered. One row reached from two playlists or passes is one answer naming
  each. Any synced listing unreadable, short, or empty with nothing saying it
  holds none stops every offer. A playlist neither the account's list nor its
  id finds is gone: it offers none of its own tracks and holds what its
  finished jobs recorded, read per playlist (round two); nothing readable
  recorded is not read whole.
