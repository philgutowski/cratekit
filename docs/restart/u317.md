**Three kinds of files backup.** `modules/tools/backup.py`'s `_plan_files`
plans one, before any command exists, so the dry run and the real run stay one
decision.
- **full check**: the mirror as it always was (`rclone sync`, fast listing, or
  folder by folder with `--full`). It runs for any of these reasons:
  - `--check` or `--full` was given;
  - the last full check is seven days old or more (`backup_facts.FULL_CHECK_DAYS`);
  - the record is missing, damaged, of another schema, or kept for another
    root, volume identity, mirror, archive root or exclude set;
  - the library's files fact does not carry the record's token;
  - the walk refused;
  - more than 10,000 paths changed;
  - a changed name is in decomposed Unicode form.
- **quick**: the library is walked (`modules/tools/backup_record.py`, stat
  only, rclone's own exclude and link rules) and compared with the record.
  Only the difference goes through rclone, with `--files-from-raw -`,
  `--no-traverse` and no listing of the remote:
  - `quick-send` copies what was added or changed;
  - `quick-resend` copies, with `--ignore-times`, a file whose hash moved under
    a kept size and time, or whose record entry was a doubt;
  - `quick-archive` moves what was removed into the run's dated archive, the
    folder the full sync's `--backup-dir` uses.

  Each command runs only while the root is still the volume the plan walked.
  The archive also checks that every removed path is still absent.
- **skip**: nothing but the fact file changed. No command runs, and the files
  age is published.

**The record** is installation state (`backup_manifest.json.gz`), never on the
volume, since the library's state folder is inside the mirrored tree. It holds
path, size, time in nanoseconds, and a sha256 for any file modified within ten
seconds of the walk (the racy window).
- It is removed, and its token struck from the library's files fact, before
  the first transfer it describes. It is written only after the portion
  completed, from the walk before the transfer and one after it: an entry is
  trusted only where the two agree, else it is a DOUBT that matches nothing.
- A record is trusted only while the library's files fact carries its token,
  so a run of another installation or of an older build sends the next run
  full.
- The fact file is the one file a skip does not send. Every run rewrites it
  after its transfer, so the remote's copy is a run behind under every kind.

**The database.** Below the process check, the database set is hashed with the
settings folders and an outside share by size and time, and the fingerprint is
compared with the one the last completed snapshot kept, for the same database
path, snapshot root and identity. Equal is `unchanged`: no copy, age
published. Otherwise the dated snapshot runs as before. Its fingerprint is
kept only when:
- a second process scan confirms both processes gone;
- a second fingerprint agrees with the first;
- the identity marker was written.

`--check` and `--full` force a snapshot. The weekly full check is the mirror's
alone, since a queued job plans each portion in its own item after the one
before it published.

**Ages and reports.** Each portion's fact records its kind and a summary
(counts, seconds, why, the record's token). The file gains `full_check`, read
by `backup_facts.full_check_age` and carried on the files entry of
`backup_facts.ages` as `full_check_due` and `full_check_overdue`; a damaged
entry there is a reason, never a refusal of the age a session reads. The verb
warns `backup-kind` with the kind, the counts, rclone's sent and archived, the
seconds and the next due date, and its ages carry `full_check_due`. Doctor's
`backup.age.*` names the kind that set each age, and the new
`backup.full_check` names the last full check and the next due date.

**Decided by the session, recorded here.**
- **The flag** `--check`, with `--full` kept as the folder by folder listing
  and counted as a full check.
- **A failed or partial run leaves no record**, so the next run is full, the
  conservative one of the brief's two options.
- **The weekly full check is the mirror's**, and only the flags force a
  snapshot.
- **The fact file rides with a quick run and is left out of a skip**, and out
  of the reported counts.
- **The quick limit** of 10,000 paths, a choice of speed.
- **The record in installation state**, never on the volume.
- **Doctor's due line is INFO at every age**, since a due check is what the
  next backup does by itself.
