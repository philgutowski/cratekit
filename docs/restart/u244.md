**What landed.** `tagging/searchers.py` asks `beatport` then `discogs` by
default (`WALK`); Traxsource and Bandcamp stay in the tree on `SCRAPED_WALK`,
which the old suites drive, and `SOURCES` names all four so a record written
before still summarises. Discogs is one database search (type release, the
artist, and the title with its last bracketed group left out) and then up to
three of the releases it names, each read by its integer number. A release is
taken when one of its tracks, the sub tracks of an index row included, or its
own title for a single, and an artist match, the track's credit before the
release's, Discogs' "Prodigy, The", "(2)" and "*" forms read as a tag spells

that is not the fallback's is written, chosen by one `choose_word` shared with
`published.choose` and resolved only by `routing.suggest_tag` with
`source="discogs"`. The answers: an empty result set is MISS; a 401, or a
token that is not one printable word, is a refusal built from
`secrets.CredentialRejected` and remembered so the token is never sent again
in the process; a 403, a challenge or a 429 past the existing ladder is
BLOCKED and remembered; a 5xx, a transport failure or a body that is not JSON
is UNREACHABLE; JSON of an unknown shape is PARSE_BREAK; a gone release is
passed over, an unread one outranks a miss and a styleless match. With no
token Discogs is `not-asked`, its note saying how to record one, and rides
`unread`, so the file is `sources-unread` and never `no-hit`. One asker per
process (`for_discogs`) holds the token read from the keychain, one `Pacer`,
the last `X-Discogs-Ratelimit-Remaining` (ten seconds' wait at five or fewer)
and the remembered refusals; `Fetched` gained the answer's headers. The token
goes only in `Authorization: Discogs token=...`, every note is scrubbed of it,
and it is out of the asker's `repr`; the agent is `Cratekit/<version>`.
