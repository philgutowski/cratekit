**The session before: U132, issue #300, `fable/300-taxonomy-behind-shipped-schema`, 2026-10-10.**
A library's taxonomy copy that is behind the shipped schema is now named,
never skipped silently. NEW VERB `crate taxonomy upgrade`
(`cli/verbs/taxonomy.py` over `core/taxonomy_upgrade.py`) plans the shipped
classes and buckets the copy lacks, raises its `schema_version` to the shipped
one, and holds, with each reason named, any entry that would clash with the
copy as edited: a word another bucket already files, or a candidate that
would not load. It never changes an entry the copy declares and never touches
the top level sections, vocabulary or fuzzy rows. Added blocks are cut from
the shipped text with their comment run and child tables, verified by parse
equality, and placed where a fresh setup would put them, before the copy's
entry that follows them in shipped order. The gate `taxonomy.upgrade.apply`
is explicit; the digest covers the before and after texts and the items,
never the path, so a rehearsal on a disposable copy of the same file matches.
After the answer the plan is taken again and refused as stale if it moved,
and the copy is read once more as bytes and refused as stale if they no longer
read as the planned text. Those bytes are kept beside it as
`taxonomy.toml.<date>T<time>.bak`, so a CRLF copy's backup is byte for byte,
and the upgraded copy keeps a CRLF copy's line ending (mixed endings are
written as LF and said). The new copy is written atomically and read back
through the loader; a failed read back puts the old bytes back, reads that
back too, and the refusal says whether it took and where the backup is. A
plan with nothing to write ends NO_OP without asking. THE BACKUPS SIT IN THE
COUPLED FOLDER, which a capture copies whole and a restore replaces whole, so
each one (about 35 KB) rides every later snapshot and nothing sweeps them;
no check reads unregistered files there. Doctor gains `taxonomy.schema`: INFO
naming both versions and each missing class or bucket with the verb as
remedy, OK when current or when the library has no copy (every verb then
routes by the shipped template), INFO naming `taxonomy.template` when the
shipped template cannot be read, FAIL only when it reads but does not load.
