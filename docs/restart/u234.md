**U234, #623, a stopped account order read off its moves' path is never
written into rekordbox as a reorder, built in the cloud lane on 2026-11-07.**
A large card: it changes what `crate sync pair` writes into rekordbox and
onto the account for a pair finishing a stopped order. Filed from Phillip's
attended sitting 87 on v0.13.1: five of sitting 86's stopped orders, four of
them GIG READY sets, stood in orders none of the stopped write's moves
leaves (`pair_stopped.positions` empty), and the rehearsal plan read each as
"the account was reordered since, so its order is read as yours" and planned
a rekordbox `order` of the half done account order. Nobody had reordered
them.

**What landed.**

- **Off the path is not a reorder on that alone** (`plan_pair` in
  `sync/pair_cli.py`). An account off the stopped write's path is finished as
  one on it is (U225): it is read as the write would have left it had it
  finished (`pair_stopped.finished`) and the merge gets the `Stopped` record,
  so the side that led the write leads unless rekordbox changed order since.
  No rekordbox `order` comes from the reading. Under GIG READY the rest of
  the order is sent as a finish, held to the plan's own reading by `expect`
  and R-1411's `agreed`; outside it the account is left and rekordbox keeps
  its order (R-1404). A pending stop agreed off the path, past U231's hold,
  is finished the same way.
- **A person's reorder still leads once settled readings show it**
  (`_moved_since_stop`, `pairs.StopReading`, `Pair.stop_seen`,
  `PairStore.see_stop`). The first reading off the path a plan takes after
  the stop is kept on the pair with its run and moment, and a plan at least
  `AGREE_AFTER` later reading the same order settles it; a different order
  before then is kept afresh. Once settled, an order off the path differing
  from it, on the tracks both hold, is kept as the order after and holds the
  pair, `sync-pair-account-settling` with problem `order-moved-since-stop`,
  nothing written, until a reading `AGREE_AFTER` later agrees: only then
  does the account lead. A reading on the path is finished and never kept,
  since it may be a lag of the whole write, and it, or a reading back at the
  settled order, ends an order held as the one after. Kept for that run and
  at or after its moves began (`_kept_after`); cleared when the snapshot
  moves. A hand pairing has no record, so nothing it reads leads.
- **A stop known to have sent no move is not one** (`pair_stopped.MOVES_RECORDED`,
  `StoppedWrite.sent_nothing`). Since U231 a write records its moving step
  before its first move, so every ordering step now says so, and one carrying
  that with no moving step beside it sent nothing: an order off its path is
  the person's at once, as before U234, which keeps R-1420's refused order
  (#619, merged in while this was built) as its card made it. A record
  without the marker, Sitting 86's and every v0.13.1 stop, sent moves before
  U231 recorded them, so it keeps the conservative reading.
- **The gate says which it read.** The pair's line says the account stands
  where none of the stopped write's moves leaves it, which is the provider's
  partial state as often as an edit; for a pair whose settled readings show
  a reorder, that it was reordered since syncs after the stop read it
  settled; for a stop that sent nothing, that none of its moves was sent;
  each naming the stop whether or not its bases were folded. The
  `sync-pair-finishing` note says the same.
