**U223, #555, a Ctrl-C during analyze run is resumed by the printed command
even when it lands just after a rename, built in the cloud lane on

`crate analyze run FOLDER` failed one track for good as `source-missing`.

**The cause.** `artifacts.produced` calls `staged_path`, which removed the
item's whole staging directory before writing the report, and `handle_run`
calls `produced` after `_finalize` has recorded the rename intent and
renamed the file. So the intent was gone by the end of the attempt that
wrote it. The window that loses it is `jobs.drive`'s own interrupt
checkpoint: a Ctrl-C landing at any point in the handler's work, a decode of
several seconds, is noted, the handler finishes, and the produced item is
released uncommitted. The resume then finds the source gone and no intent.

**What landed.** In `src/cratekit/analysis/artifacts.py`, `staged_path`
clears everything in the item's staging directory but `rename-intent.json`,
so the intent outlives the attempt that renamed the file and a resume
interrupted in the same window too. `_finalized_twin` in
`src/cratekit/analysis/cli.py` reads the intent first and, when it is gone,
the item's own uncommitted staged report (`artifacts.staged_report`, read by
`_staged_twin`): an `analyzed` report whose `renamed_to` is its path's name,
or a resume's `resumed_after_rename` report, the path in the item's own
folder. That also finishes a job the shipped code interrupted in this window
and nobody resumed yet. No folder scan. The evidence is dropped where it is
known false, by `artifacts.discard_rename_evidence`, the intent and the
staged report together: a taken target name, a refused rename, and the start
of an attempt whose source is still a file. Neither the intent nor a report
is read through a link, and the discard does not reach through a linked
staging directory, the rule `staged_path` already kept. No other job handler
renames inside its attempt: `handle_restamp` renames nothing, the tagging,
adoption and sync workers rename nothing, and the naming and repair verbs
rename in gated plans with no job staging. No beat grid is touched;
`_finalize` writes the same eight fields as before. `docs/GUIDE.md` says a
Ctrl-C at any moment, a renamed track included, is finished by the printed
command.

**Decided, recorded here.** The location of the intent is unchanged, inside
the item's staging directory, so a job queued by an older build reads the
same path; the staged report fallback covers the jobs the shipped code
interrupted. Card size large, since it changes `staged_path`, a path that
deletes, and adds a removal of the intent.
