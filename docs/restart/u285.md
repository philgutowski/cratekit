**U285, #800, Cratekit's verbs read a DEADCA7 push whose rows carry the zero
date, built in the cloud lane on 2026-11-13.** Filed from attended sitting 98,
A57 (#415): the first real DEADCA7 push, made into a disposable copy, made
`crate organize` and `crate converge` fail `INTERNAL` with `OverflowError: date
value out of range`. The card's title carried U283, which #799 and #817 had
taken, and U284 was taken too; renumbered to U285.

**The cause, driven.** DEADCA7 0.2.3 stamps `created_at` and `updated_at` as
`0001-01-01T00:00:00Z` on its folder, its playlists and every membership.
pyrekordbox 0.4.4's `tables.string_to_datetime` answers `astimezone()` of the
stamp, made naive. West of UTC that is before year 1, so the conversion raised
and the whole row failed to load; organize's `yours` step and converge's root
set both walk `db.get_playlist()`. East of UTC it loaded as `0001-01-01 09:00`,
which a reader converting it again could not convert either.

**What landed.**
- **The seam**, `core/rb_dates.py`, installed by `rb_writer.open_db` before the
  binding is made, so every handle on the database or a copy reads the same
  way; nothing else in `src` constructs the binding to read rows. It wraps the
  binding's module level conversion, which its `DateTime` column looks up at
  every row, so a wrapper installed after an earlier query still applies.
  A stamp the conversion places between `FLOOR` (0001-01-02) and `CEILING`
  (9999-12-30) reads exactly as the binding reads it. One it places outside
  them, or cannot place (`OverflowError` for a stamp with an offset,
  `ValueError` naming year 0 or year 10000 for one without), reads as the bound
  on its side, naive and convertible back in any zone. Text the binding cannot
  parse fails with the binding's own error, and a failure at any other year is
  raised as it came, so no real error reads as the zero date.
- **A bound is never written back.** A loaded value is committed state, so the
  rows stay byte for byte. The binding's `commit` also copies each playlist's
  `updated_at` into its `masterPlaylists6.xml` node when they differ; the seam
  wraps that update too, so a bound is dropped and an update carrying nothing
  else changes nothing. Another app's node keeps its Timestamp; the library's
  own stale nodes still sync.
- **The fixture**, `tests/deadca7_fixtures.py`: `ZERO_STAMP`, the producer's
  text exactly, on every row the push writes (the cue rows' real stamp was not
  read, so they take it too), and `west_of_utc()`, a POSIX US Eastern rule that
  needs no zone database, since a run at UTC passes by accident.

**Decided here.** The seam is a wrapper of the binding's module global, not a
column type swapped onto each table, because the binding's column looks the
function up at every row and a swapped type would not reach a result processor
SQLAlchemy had already cached. The size grew from medium to large in the second
fix round, which changes what a commit writes into the XML; the table covers
every guard either way.
