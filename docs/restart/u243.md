**What landed.**

- **`deletion/candidates.py`.** `_streaming` excuses an unmapped row only when
  its whole value is `/v4/catalog/tracks/<letters and digits>` with an
  optional trailing slash (`\Z`, so no trailing newline) AND the injected
  `stat` answers `FileNotFoundError` at that spelling; a file or directory
  there, any other error, or a value the call refuses keeps it unmapped. It is
  asked only after the resolver, so a rule over `/v4` wins. `ReferenceSet`
  gains `streaming`, counted in `counts`, `ignored` (not a path plus
  streaming), and `unmapped_prefixes`. The refusal names up to five prefixes
  with their counts and offers, per prefix, one entry to add to the
  `library.location_prefix_map` list.
- **`deletion/cli.py`.** The gate screen says `ignored, not local files` when
  the proof excused any row; display only, outside the digest.
- **`label/tombstoned.py`** (new). One lazy read of the tombstone store asks
  whether a provider track's artists, joined by a comma and a space as the
  downloader tags them, and its full title are a removed version, under the
  version kind and then the uncredited companion. It imports only
  `core.tombstone` and `core.review`, so the label module never imports the
  deletion package. Named `tombstoned`, not `removed`, because
  `test_no_removal_shape_appears_in_the_label_folder_path` forbids the word in
  the label folder path.
- **`label/playlists_cli.py`.** Each release's rows are judged as read; a
  tombstoned track is left out of every year and named on
  `LabelCatalogue.tombstoned`. A year every playable track of which was
  removed is not made; one the provider plays nothing of is planned as before.
  Releases the release level tombstone suppressed are read for their tracks'
  sake alone, so a removed single is judged (round two). The screens say how
  many tracks were left out, and the releases build's nothing to build
  sentence leads with the removal.
- **`label/kept_reads.py`.** Each kept track keeps its artist and title; a read
  kept before this carries none and is read again rather than judged blind.
  The document version is unchanged, so an older build reads the new keys.
- **`modules/outbound/prune.py`.** A track recorded as added to a created year
  playlist and named on `tombstoned` leaves it whatever release keeps it. A
  playlist the plan empties is said on the gate and in `totals.emptied`, and
  kept.
- **`label/heard.py`.** Hearing a dated playlist never adds a tombstoned track
  to the year, nor one the ledger records as pruned from that year (round two,
  the same class one step over), and needs no year when nothing goes in it.
- **`label/sweep.py`.** `Confirmed.suppressed_releases` carries what the
  release level tombstone dropped.
