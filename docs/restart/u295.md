**What landed.** `src/cratekit/cli/schedule.py`, three core verbs on row 25.
`install [--at HH:MM]` (default 03:17 local, off the hour and outside the
evening) writes one launchd user agent, `cratekit.sync-night.plist`, in the
person's own `Library/LaunchAgents` (one function, `launch_agents_dir`, under
`Path.home()`), and loads it into `gui/<uid>` with `launchctl bootstrap`. Its
program is exactly the absolute `crate` that ran the install, `sync` and
`night`; `RunAtLoad` false; one `StartCalendarInterval`; output appended to the
new state entry `schedule_log` (`schedule/sync-night.log` under the
installation's state). The environment is a fixed PATH (the crate's directory,
the directories the install found each binary in, the binaries' fallback
directories, the system's own), the configuration, state and provider gate
directories as the install resolved them, absolute, and the library, staging,
ISRC cache and per binary overrides set at the install, made absolute; never a
credential or a raised limit. An agent already installed is booted out first,
so a second install replaces it. `show` writes nothing: installed or not, the
time, the crate, launchd's state (unknown said as unknown, never as absent),
and the last night's line read from the state the agent carries; it fails
`schedule-agent-unusable` over any plist that is not the one install writes
(another key, program or word, a crate that cannot run, a run at load, another
calendar, a name never carried, a carried directory missing or relative, a log
outside its state) and over an agent launchd holds with no plist. `remove`
boots out and deletes; nothing installed is a no op. All three refuse on any
platform but macOS (`schedule-platform-unsupported`) and as root
(`refused-by-policy`); install and remove hold the staging lock around their
bootout, so a night in progress is never ended by it.

**The guards.** launchctl is one function, `launchctl`, run by its absolute
path with a timeout; a test reads the module's AST so nothing else imports
subprocess or names a launcher, through an allowlist of imports and of `os`
names. `tests/conftest.py` replaces the seam in every test with a refusal that
fails the test, and reads the platform as Linux, so the contract sweep and any
test that forgets refuses before launchd on the Mac too. A failed load is
booted out again and its plist removed only once launchd reads it absent;
otherwise it is kept and said. The plist is pinned by a literal written out in
the test, never read off the module.

**Decided here, recorded.** The registry entries declare no library write
surface and are not destructive, on `skills.install`'s argument: the plist and
the log directory are the person's own files, not the library's, and the
destructive session's gates would be gates over the wrong thing. A failed
replace leaves no schedule rather than restoring the earlier one (a residual
for Phillip's ruling). 03:17 as the default. The label `cratekit.sync-night`.
