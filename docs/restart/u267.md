**The seam, `rb_writer.SharedRead`.** Made by `organize` only when `--report`
is given, closed in a `finally` around both areas' planning. `handle()` opens
at the first read through `open_db` with read intent, exactly the call each
reader made (live path, `require_closed=False`, `check_app_version=False`),
so the binding pin, the canary, the schema pin and the foreign tree read run
once, and answers the same handle after; lazy, so `--only file` still opens
nothing; a failed open is not kept, so the next reader asks again and refuses
as its own open did. `release(db)` empties the session's identity map, so a
later reader reads the database afresh rather than taking a row an earlier
reader loaded, which with rekordbox running and writing would have been a
row out of date; it refuses a handle not its own. `close()` closes through
`close_db` once; a handle asked for after it is refused as a defect.
`done_reading(db, shared)` is the one place a reader closes its own handle or
releases the shared one.

**The readers.** Each takes `one_read=None`. With none it opens and closes as
before, the literal `open_db` call kept, so the run that answers a gate, every
plan an apply writes against and every write is unchanged, and the AST guard
over the collection reader still reads its open. With one it reads through
the shared handle. No `apply` closure is handed the shared handle: each opens
its own write handle with `require_closed=True` as before, and
`set_cli._inspiration_folder` refuses a shared read handed to it with
`read_only=False`. The copy, the integrity check and the soft delete guard's
reader are not touched.
