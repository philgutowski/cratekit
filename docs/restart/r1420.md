**What landed.**

- **The check reads the order of a continue whose moves never began**
  (`_ordered_by_this_run` in `sync/pair_cli.py`, read by `check`). Since
  U231 the adapter calls `begun` before its first move and the write marks
  `moving` there, so an order stopped with no `moving` step sent nothing,
  whatever stopped it: refused, parked on a cooldown, or stopped with the
  whole write by a rejected session (the last two found while round one
  ran and confirmed by it). Such a playlist must still stand as the plan
  read it with this write's additions after it (`_beyond` with `ordering`
  false); anything else refuses `decision-stale`, "was reordered since the
  plan", nothing written. A pair whose moves began, and a finish of a
  stopped order (R-1411's `agreed` holds it at the adapter), are read as
  before.
- **Every continue of an order that moved nothing hands the adapter the
  check's listing to agree with** (`_write_account`, round one's row 2):
  whether an earlier command began the order is read before this command
  marks it, from the run's steps or, when they cannot be read, the record
  carried beside them (round two's row 1). A finish keeps exactly what
  R-1411 gave it. Every existing refusal is kept.
- `apply_pair`'s docstring says what the check's listing is held to now.
