**What landed.**

- **`src/cratekit/cli/progress.py`, one writer behind `Context.progress`.**
  Called with a line, as every progress caller calls it, it writes the line
  in human output and a `line` event under `--progress json`; `step`, `job`
  and `end` carry the structure, and in human output write today's English
  or nothing. Every write is flushed under one lock, and one that fails is
  dropped, as is one to a `None` stream (a process started with standard
  error closed). `writer_for` hands a verb events under the flag in either
  output mode, English in human output, and nothing in JSON output without
  the flag, as before. `Writer.beside` gives a verb run within this one a
  writer of the same form on the same stream.
- **The job watch.** `watching` starts a thread only under events: it reads
  the job's state and `jobs.progress` counts off the queue as the drive
  starts and every `WATCH_SECONDS` (one second), writing a `job` event on a
  change, and the caller always writes the job once more after the drive.
  The queue is imported only when a watch reads it.
- **`src/cratekit/cli/tail.py`.** `Chain.say` hands a writer with a `step`
  form the step's index, count, name and command (or detail), and any other
  callable the same English line; `Chain.call` takes the job it drives and
  watches it; `settle` names it.
- **`src/cratekit/cli/__init__.py`.** The root option `--progress json`
  (dest `progress_format`, its value spelled `PROGRESS_JSON` so `crate`

- **`src/cratekit/cli/output.py`.** `PROGRESS_SCHEMA`, the common and per

**Decisions, recorded.**

- **Not a sixth payload surface.** No envelope carries an event, so
  `schema_names` stays R32's five and the lock is untouched; the event's
  document is pinned whole.
- **A step event carries `detail` beside `command`.** `Chain.say` also says
  things that are not a command (the preflight's two checks, the pass's run
  and how to continue it); `command` is null there and `detail` holds the
  words, which the envelope carries too.
- **The person's copy of a refusal stays on standard error after `end`.**
  An app stops at `end`; the guide says a line that does not parse is not
  an event.
- **The closed pipe guard is not the flag's alone.** `_to_stderr` drops a
  standard error write a closed reader cannot take in both output modes,
  with or without the flag, and writes nothing to a `None` stream. Without
  the flag that changes only a run whose reader closed standard error, which
  ended in a BrokenPipeError traceback and exit 1, and one started with fd 2
  closed, which put the person's copy on standard output after the
  envelope; every other byte is the same (the review compared five forms of
  `sync land`, base against branch).
- **The job is sampled, not announced.** The watch reads the queue each
  second rather than hooking the engine's transitions, so no engine path
  changes; a job shorter than a second can go from `queued` to its end
  unseen running (a residual).
