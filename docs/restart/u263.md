**U263, #692, `crate analyze run` measures an M4A on a current librosa,
built in the cloud lane on 2026-11-12.** Filed from the speed survey of
2026-11-12 as a defect: a fresh install of the analysis extra resolves
librosa 1.0.0, whose `load` reads through libsndfile alone and dropped the
fallback decoder, so every M4A, AAC or ALAC, came back `skipped-undecodable`
from the head and vocal inactive from the vocal pass. Medium: it changes how
the analysis decodes and writes nothing new itself, though it feeds the tag
write and the rename.

**Reproduced first.** On this container, librosa 1.0.0 with libsndfile
1.2.2 raised `LibsndfileError` on an AAC and an ALAC M4A and decoded the
same audio as WAV, FLAC and MP3. The failing test went in first
(`f90593be`): both M4As `skipped-undecodable` through `detect.analyse_file`.

**The choice, a decode through ffmpeg.** `analyze run` and `analyze vocals`
already declared `binary.ffmpeg`, and the downloader needs it, so no new
dependency and no install step. A ceiling below librosa 1.0 was the other
way, and would hold the analysis on releases whose fallback, audioread, they
themselves mark for removal.

**The one decoder, `analysis/decode.py`,** which the head
(`detect.analyse_file`), the vocal pass (`vocal.decode`) and the energy
measure of restamp and calibrate (`energy.features_from_path`) call, and
where U264 (#693) puts its one add mix:

1. `librosa.load` exactly as each site called it, first, and whatever it
   returns is returned untouched. On 1.0 that is every file libsndfile
   reads; on an older release, those and the files its own fallback reads,
   an M4A among them. So nothing analysed today changes, on any librosa.
2. Only when that raises AND `soundfile.info` cannot open the file does
   ffmpeg decode it: the first audio stream (`-map 0:a:0`), `-xerror`, 32
   bit float WAV on a pipe, the path as `file:` so a colon is not a
   protocol. The header ffmpeg wrote gives the rate and channels; the
   samples take librosa's own `to_mono` and `resample(res_type="soxr_hq")`,
   and an offset and duration are cut in native frames with `int`, as the
   soundfile read cuts them. Nothing is written to disk.
3. Any line ffmpeg says at `-v error`, except from the three decoders it
   gives a cover (`mjpeg`, `png`, `bmp`), fails the decode, as does a non
   zero exit: `-xerror` alone exits 0 with the part before mid file damage.
4. A failure on a file libsndfile opens is raised as before, so a damaged
   FLAC is still the caller's `skipped-undecodable`.
5. No ffmpeg raises `DecoderMissing`: the head answers a new terminal,
   `skipped-no-decoder`, the vocal pass `vocal-no-decoder`, and the energy
   measure its None (`features-unavailable` in restamp, unreadable in
   calibrate).

**Doctor.** `binary.ffmpeg` already failed with the analysis module on and
ffmpeg absent; its detail now names the verbs a failing binary row stops
(`verbs_requiring`), and `analyze restamp` and `analyze calibrate` declare
`binary.ffmpeg`, since their energy measure decodes the same way. So with
ffmpeg missing, `crate doctor` names `analyze run`, `analyze vocals`,
`analyze restamp` and `analyze calibrate`.

**Bounds.** The floor rises from `librosa>=0.10` to `librosa>=0.10.2`:
0.10.0 and 0.10.1 import `pkg_resources` and do not import at all on a fresh
Python 3.12 (measured here). No ceiling.

bounds allow.** `tests/test_analysis_decode.py` (the ffmpeg half, numpy and
