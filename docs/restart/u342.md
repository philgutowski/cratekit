**What landed.**

- **The naming engine's stamp**, `core/naming.py` `stamp_head(name, *, key,
  bpm, template)`: the head `render_all` renders (`_render_head`, the key
  padded by the template's `key_pad`) set before the whole name, so every
  byte is kept and a marker only head follows the fields where a lossy render
  places it (`[MP3] Tango` becomes `09A - 99 - [MP3] Tango`). It answers None
  for a name with a head at the front or the end, one with nothing but a
  marker after the head, a value no head carries (a key off the wheel, a
  tempo of 1000), and a result that does not read back as a complete head of
  those values over the same body. Not `build`, which dedupes and shortens
  the stem to a path budget and so would change bytes the brief keeps.
- **The plan**, `analysis/head_adopt.py` `plan_row`: a title whose leading
  head carries no field and whose row has a Camelot key and a tempo above
  zero is planned `stamped`, a new writing action beside `adopt`
  (`WRITING`), counted apart in the outcomes, with every surface before and
  after, in the digest, and held out by `--leave` as `held-out`. A headless
  row missing either half is left as the new `no-head-unanswered`, its notes
  naming the half (`key-empty`, `key-not-camelot`, `tempo-zero`), never
  stamped half. Its title tag must read as the row's title, or already as
  the stamped title, a run stopped after the files continuing; anything else
  is `title-tag-differs`. `initialkey` takes rekordbox's key as for a
  corrected row. `no-head` now names a headless title the engine refused.
- **Unchanged**: the scope, the reading, the gate, the digest's shape, the
  writes (`Title` under `adopt-rekordbox-head`, the title tag, `initialkey`),
  the record `head_adopt_before` and `restore run`'s file half, which puts a
  stamped row and its file back with no head. A row with a head runs the old
  path; round one compared 18,900 synthetic headed rows base against branch
  and none differed.
- **The verb's words**: the rows left warning names the missing half
  (`Yankee (no-head-unanswered: key-empty, tempo-zero)`); the written warning
  counts the files that took a head on a title that had none and says no file
  is renamed, no longer that the names keep their old head; the registry
  summary names headless titles.

**Decisions the session made.** The outcome is spelled `stamped`, the brief's
word. The tag of a headless row is held to byte equality with the row's
title, the strict reading of three surfaces one answer; the near misses that
leaves are a residual. A title with a head at its end, or nothing after the
marker, is refused rather than given a second head (review round one). A
partially headed title is possible only under a template no configuration
builds and stays `no-head`. No behaviour scenario was added under
`tests/behaviour/`: the card restructures nothing, and an adopt scenario would
need an analysis file, which carries a grid, the reason `analysis_check.py`
writes none.

**Hard constraints, held.** No beat grid, tempo element, tempo tag or average
BPM in any container: the stamped write goes through the same `write_files`
and the same `Title` only policy as adopt, the scan walks both modules, and a
stamped item through `write_files` in every supported container leaves no key
of `FORBIDDEN_TAG_KEYS` (`test_a_stamped_file_carries_the_tempo_as_text_and_no_tempo_tag_in_any_container`).
`KeyID`, the BPM column, the analysis files and the file names are compared
byte for byte across a stamped apply. Neither gridless suite was edited.
