**The kill set, `scripts/killset.py`,** standard library only; it runs no
test and writes no source file. `list` reads every table under
`docs/mutation/` and says what each recorded kill is today: live when its
file exists and its `old` text occurs exactly once, stale, ambiguous or gone
otherwise, the same substitution recorded twice counted once. On `ff8e5ec`
it prints the brief's numbers exactly: 728 tables, 9,258 rows, 8,541 killed,
7,093 live in 315 files, 1,069 stale, 70 ambiguous, 200 gone (196 of them in
two tables of an older form that name no file), 109 duplicates. `rows PATH
...` writes the live rows of files or directories as a row file for the
driver, each naming the table and id it came from, with its tests: the row's
own subset, or the files its recorded kills name when it had none or was
promoted. `rows --after BEFORE.json` writes the same kills after a refactor,
anchored where their text is now. `check BEFORE AFTER` exits 1 unless every
row killed before is killed after or is mapped, with a reason, to a row that
is. A replay table committed under `docs/mutation/` is read as where a
source now lives and counted as no table of its own, so a guard one card
moves stays in the kill set for the cards after it.

**The replay pass, `scripts/mutate.py`.** A third pass kind with no row cap,
because it chooses no rows: every row carries `source = { table, id }`, read
before anything runs against the table it names (the file exists under
`docs/mutation/`, holds that row, the row recorded a death, and a row whose
file or text is not its source's says why in `moved`). `[[mapped]]` entries
are validated and carried into the table. The baseline, the null control,
the subsets, the promotion of a zero and the restore checks are the paths
every pass runs. `--resume` reuses a replay's rows only from a sidecar of
this commit with no tracked file changed since; a light or a full pass
resumes as it always did, and writes the sidecar it always wrote (the review
compared one from `main`'s driver with the branch's, equal but for the
time). The 25 and 45 caps stand.

**The comparison, `scripts/behaviour_compare.py` and `tests/behaviour/`.**
`capture --out DIR` runs the scenario files as a serial pytest run of their
own with its base temporary directory at one fixed root inside the system's
temporary directory, and the product imported from a copy of `src/` at a
fixed directory beside it, so every path a scenario prints or writes is the
same text in two captures; `--rev` copies that revision's `src/` out of git
instead, so a branch is compared with its base by one harness. The suite's
conftest isolation holds for the run by construction, and the scenarios
import the suite's own fixtures. A conftest beside them moves the roots into
the scenario's own directory, pins the clock (`datetime`, `date`,
`time.time`, the two duration clocks), the id sources (`uuid4`,
`secrets.token_hex`, and `secrets.token_bytes`, where the rekordbox binding
draws a row id) and the binding's own row stamps, sets file times between
commands, and refuses before every command unless the configuration and
state directories the product resolves are inside the scenario's directory.
A capture holds, per command, the arguments, both streams and the exit code,
and afterwards every file by path, bytes and permission bits, and every
SQLite database as its schema, its settings and a sorted dump of every
table. `compare A B` prints each difference and exits 1 on any.
