**R-1646, #788, a name crediting the artist before a part ending in a version
matches only a row that writes the same split, built in the cloud lane on
2026-11-12 and 13.** Filed at the review of #781 (R-1636). Large: the
matcher decides which catalogue row's genre is written onto a file, for good.

**What failed, reproduced on the base.** Since R-1636 the file's side of the
record shop matcher in `tagging/searchers.py` read "[KEY - BPM -] Artist -
X", X ending in a version word, both ways (`_title_starts`' `either`): the
artist's part as a self titled title, and X as a title, since only a list of
version words tells a title "Vocal Mix" from a self titled track's version.
So a Beatport "Vocal" row or a Discogs "Vocal Mix" track wrote its genre onto
"08A - 124 - Bernard Badie - Vocal Mix", and a self titled row "Bernard
Badie" onto "Bernard Badie - Sunrise Mood Extended Mix". The tests written
first, section I of `tests/test_title_matcher.py`, were 32 red on the base.

**The brief could not be built as written.** It asked for the first name to
take its own row "Bernard Badie" under another mix and the second to refuse
the self titled row. The two names are one shape and the rows one shape;
only a list deciding "vocal" is a version and "sunrise mood" a title tells
them apart. On the standing line (#770's open question, a miss rather than a
wrong genre), the conservative option was built and a Question for Phillip
posted on the card, recommendation first.

**What landed.**
- `_title_starts` returns the shape instead of a both ways start. In it the
  name is read by its whole name and by its two splits into a title and a
  version (`_name_splits`): the artist's part titled, past a marker, a track
  number or a feature credit, with X as its version; and X titled up to its
  trailing run of version words, the rest its version.
- A catalogue row writes its own splits by structure only, never a list
  (`_row_splits`): before the bracket groups it ends with, or before a dash
  tail that is a version; Beatport's name and mix split together
  (`_beatport_readings`). `Readings` carries a third set, and `_meet` meets a
  split only with a split. A plain row "Vocal Mix" confirms nothing, since
  Discogs lists a single's versions as its track titles.
- A whole name whose first part is the artist's own credit before any
  feature credit (`_credits_before_featuring`) is read unshed, so a feature
  credit cut from it never leaves the artist's name (round one).
Traxsource, Bandcamp and Discogs go through `_title_matches` unchanged.
