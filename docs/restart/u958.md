**What landed.**

- **`core/rb_positions.py`, the rule, one place.** `contiguous_positions`
  (pure): per playlist the live rows, by `TrackNo` then row id, numbered 1 to
  N, and every row marked removed that holds a number moved to 0.
  `unplaceable` names a playlist holding an unreadable marker or a live row
  with no number, which is left whole. `numbering` gives each playlist's live
  count, reach and whether it reads 1 to N, for the plan and the doctor.
- **Where it runs.** `remove_memberships` and `add_memberships` record the
  playlist they wrote on the write handle's session (`record_touched`,
  cleared by the session's commit and by any rollback), and `commit_guarded`,
  after the whitelist and before the binding's commit, runs `close_gaps`:
  flush, read the recorded playlists from SQL, plan, write the live rows
  through U955's `renumber_memberships` with the stamp and the marked rows'
  `TrackNo` alone (`_park_marked`), and prove the whole from SQL
  (`gap_violations`); a refusal rolls back. `remove_playlist_node` opts out:
  a removed playlist keeps every number, as rekordbox's own removed playlists
  do. Every verb that adds or removes a membership inherits it: `adopt move`,
  `route resort`, `inbox analyzed`, `sync pair`, `favorites refresh`,
  `organize`'s mirror edits, the landings. `sync removed` keeps R-1830's
  measured rule unchanged.
- **`crate repair numbers [--playlist NAME]`** (`write/numbers.py`,
  `write/numbers_cli.py`, core, not the `repair` module, since the gaps were
  left by core writes): the backup acknowledgment, a plan on a read handle of
  every live playlist under the product's top level nodes (the taxonomy's
  tree, intake, inspiration, catalog and long tracks nodes, each `Custom
  Playlists <year>` folder, the folder of the favourites class's source when
  one live playlist carries the name) and any named, never another app's
  folder, whose live rows are not 1 to N, each with its count and reach;
  `repair.numbers.confirm`, explicit, over a digest of every row that moves;
  the write takes the plan again, refuses a moved digest, records the
  playlists and commits through `commit_guarded`; read back from SQL. A
  playlist whose order cannot be read is held and shown.
- **`crate doctor`'s `library.playlist_numbers`**, off a disposable copy once
  rekordbox is known closed, the repair's scope: INFO with the count and the
  repair when any, OK when none. Its copy preamble is shared with
  `library.paths_resolved` (`_copy_withheld`, `_copy_unopened`).

**Decisions, recorded.**

- **The soft delete stays** (requirement 2). Every reader in src treats a
  marked row as absent (R-758) and the node removal's confinement is built on
  it; a hard delete would need every caller's commit to admit a delete of
  membership rows with its own proof. The marked row goes to `TrackNo` 0, so
  it never shares a place with a live row, and rekordbox's Remove from
  Playlist, which takes the row numbered as the shown position, never lands
  on it. What rekordbox does with a marked row at 0 is a residual.
- **A marked row moves `TrackNo` alone** (review round one, B1): its
  `updated_at` is the moment it was removed, which `sync pair` reads against
  the account's changes; restamping it read a track put back on the account
  after the repair as removed later and took it off both sides.
- **The count.** Moved live rows take U955's stamp, the count the binding's
  commit leaves and now. With nothing buffered (the repair alone) the closing
  up counts as one change: the count moves by one in SQL and the registry row
  is expired for the binding to read again. With only marked rows moving, no
  stamp and no count. A row the same commit also wrote through the binding (a
  row added or marked there) is stamped again by the binding with its own
  count, as every row it writes is.
- **Ties** (R-1852): by row id, as every reader here orders them.
- **The repair's scope** is the session's call on the brief's "the product's
  trees": the top level nodes the taxonomy names plus the twin folders and the
  Favorites folder, Phillip's own playlists only when named.
