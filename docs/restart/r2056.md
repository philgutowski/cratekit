**What landed.**

- `write/vox_tag.py`, the one reader of who carries the tag
  (`vox_tagged`, moved whole from `adopt/placements.py`, which the write
  layer cannot import) and the `Vocals` / `vox` names, which
  `metadata_cli` imports from it. Adoption and the native landing read it
  as before.
- `rebuild.derive_from_taxonomy` takes `carries_vox`: given one, a
  calibrated library files the vocal sub by the tag's answer, never the
  score. `rebuild.vox_carrier` builds it from one handle and the rows,
  matching a file to its one active row as the check does; a library with
  no `vox` tag carries it on no row. `_Tree.membership` reads the tag only
  where it could file something, a calibrated library whose declaration has
  a vocal sub. A caller that reads no database passes none and keeps the
  score, the rule the landing writes the tag by.
- `declared_membership` returns `Membership(placements, not_compared,
  untagged)`, `untagged` being the vocal placements the score makes over
  the same readings and the tag does not.
- `convergence_check.Direction.UNTAGGED` and `ConvergenceReport.untagged`:
  a vocal sub membership the score places in that bucket and the tag does
  not is a difference (`converged` waits on it), never `unexpected`, so
  never left behind. `crate converge` leads a differing tree with their
  count (`UNTAGGED_COUNT`), since twenty leftovers would cut every
  `untagged:` line off; the resort's gate counts them under `vocal
  untagged` (a plan frozen before this says `UNRECORDED_UNTAGGED`, not
  zero); a driven rebuild or resort warns `vocal-membership-untagged`,
  naming each with the step: `metadata mytags-vocals --apply` for a row
  that never carried the tag, rekordbox for one whose tag was taken off,
  or take it out.
- An untagged membership under the cut, or in another bucket's vocal sub,
  stays the leftover it was; a tagged track missing from its sub is
  `missing`, and the rebuild adds it.
