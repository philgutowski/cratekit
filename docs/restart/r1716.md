  document, `sync_removed_reads.json`, declared `NEVER_RESTORED` in

  `get` answers a playlist from the store only while the listing shows the

  `keep` holds a read only when it holds as many tracks as the listing
  counts and the stamp is at least `SETTLED` (30 minutes) older than the
  read, since the provider serves a playlist's old rows for minutes after a
  write; anything else drops an older entry. Written every 50 changes and on
  the way out, merged with what another run wrote, the later read winning
  and a drop holding against a read made before it. An unreadable document
  reads as nothing held, a refused write is said, both as warnings.

  each read as it goes, so a park part way keeps what was read.
