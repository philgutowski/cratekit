**U251, #680, the suite's idle workers take queued tests from a busy one,
built in the cloud lane on 2026-11-12.** Filed the same day from the speed
survey of `main`. A config line and its tests; nothing under `src` changed.

**The change.** `addopts` in `pyproject.toml` is `-q -n auto --dist
worksteal`: a worker that runs out of tests takes half of the busiest
worker's queue, rather than waiting while one long test holds the tests
queued behind it. The comment above it says why, with the card's measurement
and this unit's. `scripts/mutate.py` (through `pytest_addopts`, which strips
only `-q`) and `scripts/cloud_battery.py` (which passes nothing over
`addopts`) inherit it with no edit. No test was changed, skipped, marked or
reordered, and the timing calibration was not touched.

**The guard.** `tests/test_suite_distribution.py` pins `-n auto` and `--dist
worksteal` in pytest's `addopts` and in the driver's copy of them, and runs
`tests/_stealing_suite.py`, a throwaway suite that cannot finish under work
stealing without a steal: a test holds its worker until one queued behind it
has run on the other worker, and the last queued test, the one a steal takes,
fails on purpose. The driver is read against it in `tests/test_mutation_driver.py`
(a full run of 16 and a three file subset of 14, as a row's subset runs: the
collected count and the moved failure), and the battery's `failing_ids` in
`tests/test_cloud_battery.py` (the moved failure by its id and the summary),
with a second battery test holding its suite command exactly, so nothing it
passes overrides `addopts`.
