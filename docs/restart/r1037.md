**What landed.**

- **`intake/native.py`, the landing names what it made.** Under
  `collection_landed` on the landing's session record: the database identity
  (the plan's master id, DjmdProperty's DBID), the update count its commit
  left, the playlists it MADE (every playlist the rows joined that was not a
  playlist row before the landing wrote, read once before its writes), and
  every row it added with the eight columns a recorded removal keeps, read
  back from the database after the commit. A read that fails records nothing
  and warns, so the landing is never reported failed and the files are kept.
  The key and the columns are spelled in the reader and held equal by a test,
  so no package reaches a new core name (the ceiling of 446 holds).
- **`deletion/library.py`, `landed_absences`.** A landed row of THIS
  database that is neither live nor marked, and not already a removal `sync
  removed` recorded (which keeps its own sequence, so one row is offered
  once), is a removal, but only while the database holds every playlist its
  landing made, in any state; a landing that made none offers nothing. A
  record of another database, with no update count, or unreadable offers
  nothing, the last with the pass's warning.
- **`deletion/watermark.py`, the number.** An absent row has no sequence, so
  the update count at the first run that sees it gone is its sequence, kept
  in the watermark's document beside the position, under the watermark's
  lock (`sight`), and forgotten when the row is seen live again, so a second
  removal after a restore is numbered afresh. The document is version 2 and
  reads version 1 as holding no sightings; `advance` keeps them, a document
  of another database drops them with its position.
- **`deletion/run.py`, `plan`.** The absent landed rows join the removals
  after the baseline, so the watermark, the reference set, the inode and
  size proof, the gate, the Trash and the tombstone are the ones a marked row
  meets, unchanged. The run that baselines takes every row already gone as
  history (R35), since its count is at or under the position it takes.

**Decisions, recorded.** The sequence rule is the count at the first
sighting, the brief's own example. A rollback is told from a removal by the
