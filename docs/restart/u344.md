**U344, #996, the tail no longer measures energy twice on files `analyze run`
just scored, built in the cloud lane on 2026-11-23.** A large card (it
changes which files a restamp writes): the run now measures energy exactly
as the restamp does, records the calibration it scored under and whether
the energy slice held through its own tag write, and the tail passes the
run's job to the restamp, which leaves out every file the run scored under
the calibration active now whose slice held and whose energy tag still
reads the run's level. Closes R-1491 and R-1556.

**Who built it.** Planned, built and landed by one thread on Opus 5.5 at
high effort. **Reviewed by Fable at high effort**, two rounds, the cap.

**The first requirement's measurement.** Before the change, over the 23
file fixed set of `scripts/analyze_stages.py`, the run's path (the whole
file decoded and resampled, then the central 120 seconds sliced) against
the restamp's (the slice decoded alone): under a calibration fit over the
restamp's features 0 of 23 levels differ; under one fit over the run's, 1
of 23 (`set04`, run 6, restamp 5); the largest index difference 1.2e-3 on
every file longer than the slice, none on the three shorter. MP3 and M4A
transcodes (16 each): 0 of 32 differ. So the levels could differ at a
decile cut, and the run was made to measure through the restamp's own
measure, `energy.features_from_path`, rather than the tail trusting a
measure that could disagree.

**What landed.**

- `detect.energy_from_path` replaces `energy_from_samples`: the head scores
  energy through `energy.measure`, the restamp's measure.
- `energy.fingerprint`, a sha256 of the calibration mapping; the run's item
  report carries `calibration` (the fingerprint it scored under) and
  `slice_held`.
- `slice_held`: the run reads the slice's length (`slice_length`) before and
  after its tag write and records whether it held. An MP3 with no Xing
  header has its length estimated by libsndfile from the file's size, so
  the run's own write moved the slice (review round one, row 1); such a
  file is restamped. A file only ffmpeg reads answers `decoded-whole`,
  which no tag moves.
- `analyze restamp --scored-by RUN_JOB_ID` leaves those files out, with
  `scored_by` and `left_out` on the payload and in the JSON answer, the
  no op `scored-by-run` when it leaves out every file, and the warning
  `restamp-left-out-nothing` with its reason when the job named is not a
  finished run over this folder. A hand `analyze restamp`, without the
  flag, is unchanged.
- The tail passes `--scored-by` with the run's job from the pass state
  (`Chain.analyzed`), and the restamp step's detail says how many files it
  left out and why, or that it left none out and why.
- **Closes R-1491**: `features_from_path` asks `warm.kernels()` before it
  decodes, so the restamp and calibrate are warmed as a head is, under the
  lock. Measured across processes, a spawned worker's head against the
  driver's restamp, before this 21 of 23 FLACs and 19 of 32 transcodes
  agreed to the bit (a numba kernel keeps the code it was first compiled
  to); after, 23 of 23 and 32 of 32. A solutions entry files the trap.
- **Closes R-1556**: `decode.centred` reads the central window in one
  call, so a file only ffmpeg reads is decoded once, not twice.
