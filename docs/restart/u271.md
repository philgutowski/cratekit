**The change.** `scripts/cloud_battery.py`'s `compare` and `baseline` each
leave `.cloud-battery/verdict.json` at the end of a run that reaches its
reading: the commit read before the run; whether the tree was clean
throughout, read by `git status --porcelain --untracked-files=all` before
and after with HEAD unmoved; the host and the kernel's boot id; the checkout;
the interpreter; the sha256 of the known failures file; any inherited
`PYTEST_ADDOPTS`; the verdict; the collected count, how many of those tests
reported, pytest's exit code, the failing ids and the collection errors. The
reporting plugin now counts the collected and the reported tests and names
the collection errors. `scripts/mutate.py`'s `read_battery_verdict` returns
that run as the full baseline only when every key is this run's and the run
ran every test it collected, exited 0 or 1, inherited no `PYTEST_ADDOPTS`, and
its verdict agrees with its ids; any difference returns the reason and the
driver measures as before. A record that passes is built into the same
`RunResult` and held to the same green or refuse check, so a red verdict
refuses the batch. Every subset baseline is measured and the null control
runs the full suite in the driver's environment, held to the read collected
count. The table and the sidecar carry `baseline_source`, `baseline_note` and
`subset_baselines`; `--measure-baseline` measures regardless.
`last-compare.txt`, which `release.py cut` reads, now names the commit read
before the run and says `dirty` when the tree moved during it: read after the
run, a commit made while the suite ran was named as the one it measured. The
baseline header and the "at" lines take that commit too.
