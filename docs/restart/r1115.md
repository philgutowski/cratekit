The residual was measured on the U190 branch before U169 landed. Since U169 a

`acquire/cli.py` gains `read_download` and `DownloadRead`, the one reading of a
settled download: SUCCEEDED, or FAILED with at least one failed track, every
failed track carrying a cause that is not retryable, and no track still to run.
`sync land`'s `_download` and the go both read through it, and `track_name` is
the naming `declined_warnings` already used, now shared. In `label/go.py`,
`_drive` drives as before through `drive_queued` and, when that refuses (or
the engine raises because every attempted item failed), reads the job back off
the queue and carries on only over a download the reading calls settled; a
transient failure, a park and a cancel still end the go on the job's own
refusal. The `downloaded` and `resumed.<job>` checks name each refused track
and its reason, the report carries them under `refused`, a track that failed
for good gets the go's own `label-sync-download-refused` warning (a declined
one keeps the worker's `acquire-refused`), and a go or resume whose every track
was refused fails that check, runs no tail and names none. Decided here: the
shared reading is stricter than `sync land`'s copy was. A FAILED job with no
failed track, a failure recording no cause, or a track never attempted is not
settled; the review drove `jobs.drive` and found no producer for either shape,
so nothing a person runs changes in `sync land`. The new warning code is pinned
in `tests/_pinned_reserved_populations.py`. `docs/GUIDE.md`'s label sync
paragraph says so.
