**R-1890, #952, the guards that scan a split module read its parts too,
built in the cloud lane on 2026-11-23.** A medium card: tests only, no source
change, no path that writes or deletes, but every guard it touches sits on a
write path. U300 split `core/rb_writer.py`, `core/session.py` and
`core/restore.py` into parts each module re-exports, and the guards that read
one of them by its file, its `inspect.getsource` or its exact dotted name read
the module and not its parts, so a forbidden shape written in a part passed.

**What landed.**

- **`tests/_split_modules.py`**, the one place a scan reads a split module
  from: the three modules, the glob each one's parts match (`rb_*.py`,
  `session*.py`, `restore*.py`, the convention U300 named them by), and each
  module's files, joined source and dotted names. The glob also reads
  `rb_dates.py` (U285), the writer's too; one file more is stricter.
- **`tests/test_split_modules.py`** holds the glob against three independent
  lists of the parts: the `docs/DEVELOPING.md` table, the import graph (a
  core module imported by its split module and by no module outside it and
  its parts, which derives exactly the glob's sets today), and the call time
  accessor a part holds back to its module, read with the module it reaches
  unless the import graph proves it another split module's part.
- **The scans**: `tests/test_cli_contract.py` (the writer never names the gate
  or a flag), `tests/test_sync_night.py` (the night job's ban on the session
  bans each part's name), `tests/test_config.py` (the restore's typed sidecar
  suffix), `tests/test_restore.py` (the convergence fallback scan, found by
  round one, and its own `_restore_sources`), `tests/test_write_session.py`
  (its terminal check scan) and, one file over, `tests/test_label_heard.py`
  (the heard path's ban on the writer bans its parts, and now reads a from
  import's names, which let `from cratekit.core import rb_writer` through on
  the base) each read the module and its parts. `tests/test_process_guard.py`
  drops its exemption of `core/rb_writer.py`, stale since the probe table it
  named moved to `rb_probes.py` as a mapping the scan does not flag, so the
  writer and every part are held alike.
- **The soft delete guard**, `tests/_source_guards.py`: a function that
  imports the writer and returns that name is the writer's accessor, so
  `_writer().SOFT_DELETE_COLUMN` names the column, and `from . import
  rb_writer` is read as the writer. The beat grid suite's two package wide
  tests read the fixed rule without an edit; on all 860 authored files the
  base rule and the branch rule give the same answers (driven by round one),
  so it fires on no correct code and `SOFT_DELETE_READERS` is unmoved.
- **`tests/test_rb_writer_parts_guard.py`** applies the beat grid suite's
  bare `RuntimeError(` and `SystemExit` scan and its reserved code check to
  the writer and its parts, reading `_writer()._unavailable(...)` and
  `_writer()._running(...)` as the parts spell them, and adds that every
  refusal names its slug as a literal a scan can read; with fixtures for the
  accessor resolution in both directions.

**Why a new file and not the suite.** `tests/test_rb_writer_guard.py` and
`tests/test_no_beatgrid_ever.py` are the two beat grid suites, never edited,
trimmed, moved or renamed under the refactor epic, every name they import
keeping its module; both are byte for byte the base's. So the card's three
items in that file reach the parts without it: two scans by the new guard
file, which applies the same checks to the parts, and the soft delete
resolution in `tests/_source_guards.py`, which is not the suite. Each is
proved by a planted shape in a part failing it. No question was needed on
the card. The suite's other direction, that every reserved writer slug is
raised, is not copied: all twelve are raised in `rb_writer.py` itself, so a
copy could only fail together with the suite's test (round one's finding 8).
