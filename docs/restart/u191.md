`crate label playlists LABEL --releases` reads the releases a `label sync` go
settled for the label, through `dated.taken_by_goes`, the reader the dated
playlist already uses, and only those: one track read each, no roster, no
listing, no verifier. Their years are planned through the same
`folders.plan`, which walks only the years it is handed and never removes, so
a missing folder or year playlist is created, an existing one is added to, and
a year no taken release names is neither read nor written. A second run plans
nothing from the outbound ledger. A release the provider no longer has is
counted, never refused; a release named only by its review item is never
asked for and is counted on its own; a release the provider dates by nothing
takes the year its answer recorded. A sync that took nothing for the label, or
whose every release is gone or undated, makes nothing, not even the folder,
and says which under `label-playlists-nothing-taken` or
`label-playlists-nothing-left`. An answer no go has taken is not read. The
digest marks a releases plan, so an answer given to a full build is stale for
it.

A full build now lists first. `sweep.confirmed_releases` is split into
`listed_releases`, the roster and paged listing, and `confirm_listed`, the
tombstone and the verifier, and composes them, so organize, prune, heard and
mark read exactly as before. The build estimates two provider calls a listed
release at the configured provider pace, and over `FULL_BUILD_CALLS`, 500, it
stops at a new explicit gate, `label.playlists.crawl` (`crawl` or `abort`),
showing the count, the calls, the time and the `--releases` alternative, with
no release read. 500 is a convention chosen here, about eight minutes at the
default pace. Under it the build runs as before, its screen naming the calls.
The conformance contract names the crawl gate as one its sample cannot reach,
the seventh such exemption, since the sample follows no label; its own suite
drives it. `docs/GUIDE.md` says all of this.
