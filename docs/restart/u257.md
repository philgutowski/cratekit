**What landed.** `secret_violations` returns the same list, in the same
order, with the same elided spans, and the eleven `SECRET_PATTERNS`, the
placeholder rule and every message are untouched. Every match is still made
by the shipped pattern; what changed is where it is run. A pattern whose
parse opens with an optional word boundary and then literal characters, read
off Python's own pattern parser (`re._parser`, the one `re.compile` uses) so
the literal cannot drift from the pattern, is tried with `match(text, pos)`
only where `str.find` reports that literal, in order and from the end of the
last match: `finditer` with only the positions it would have rejected left
out. Nine patterns take that shortcut (`Bearer`, `eyJ`, `AKIA`, `gh`,
`github_pat_`, `xox`, `AIza`, `sk-`, and the private key block's own
`-----BEGIN `); a case insensitive one, one under an inline flag, or one that
opens with an alternation or a class gets none. The two case insensitive
alternations scan a text whole only when one of its `[:=]\s*["']` runs
passes a necessary condition: the pattern's own value part matches there,
and walking back over whitespace and at most one quote, the pattern's own
keyword alternation, asked of the engine with `\Z` on a window as wide as its
longest spelling, ends there, so the folding (the dotless i, the dotted
capital I, the long s, the Kelvin sign) is the engine's. Each declares its
three source pieces, and a pattern whose source is not exactly them gets no
gate. Without a shortcut a pattern is scanned plainly, so drift, a missing
private parser under the pre commit hook's `python3`, or any shape not
foreseen costs time and never a finding. Shortcuts are paired with the
patterns by position, never by label.
