# Reading the zeros in the independent round 8 table

Companion to `u23-round-8-independent.md`, which is generated by
`scripts/mutate.py` and holds the measured rows. This file holds the judgement
the table cannot: **thirteen rows killed zero, and they are not thirteen coverage
gaps.** Seven of them are equivalent mutations, which is a different fact and has
a different remedy, namely none.

Written down because the next reader of that table sees "13 zeros out of 45" and
the honest number of gaps is **six**.

## Seven zeros are EQUIVALENT MUTATIONS, so they can kill nothing

Each of these changes text and cannot change an answer. The reason is one
invariant the ledger reader enforces in both directions at
`src/cratekit/adopt/revert.py`, in `_digest_state`: a record spelling
`DigestState.RECORDED` and carrying no digest is refused, and a record spelling
anything else while carrying a digest is refused. So `RECORDED` and "has a
non-empty digest" are the same statement about any record that came through
`read`. `_Looked.digest` defaults to `""`, so a read that did not answer carries
the empty string.

| row | why it can change nothing |
| --- | --- |
| `D3_bytes_agree_drops_the_digest_state_gate` | a non RECORDED record carries `""`, which never equals a real sha256, and the `outcome is ANSWERED` clause behind it still refuses |
| `D4_bytes_agree_ignores_the_outcome` | a read that did not answer carries `""`, which never equals a RECORDED record's digest |
| `F5_byte_search_admits_sizeless_records` | a record with `size is None` never survives `record.size == size_here` one line later |
| `F6_byte_search_admits_unstamped_records` | an unstamped record carries `""`, which never survives `record.digest == looked.digest` |
| `F2_byte_search_drops_the_size_here_guard` | with `size_here` None the size filter is already empty, because `possible` required a recorded size |
| `S2_size_of_oserror_is_zero` | a file whose `stat` failed cannot be read either, so the digest comparison refuses on the same input |
| `X11_restore_writes_absence_as_empty` | measured rather than argued: writing an empty tuple leaves the field ABSENT on `.flac`, `.mp3`, `.m4a` and `.aiff`, which is what `clear_tags` produces |

`X11` is the one worth being explicit about, because "restore an absent field as
an empty string" is a real defect shape and the module's own docstring names it.
It was driven on all four containers before being called equivalent. The
docstring's reasoning is right about `write_tags`, which skips a None; it is the
`write_tag_values` path with an empty sequence that happens to coincide.

## The one zero that was closed rather than recorded

`X6_adoptable_widens_to_online_only` admitted `Readability.ONLINE_ONLY` to the
adoptable set and killed zero tests, which means nothing stopped a cloud-backed
track being routed and having a tag written to it. The existing census test
proves the CATEGORY is named and never that the naming reaches the disposition.

It is closed by `tests/test_adoption_hardware.py`, on a real FAT volume, and the
closure is measured in `u23-round-8-independent-composites.md`:

* the same X6 row now kills **1**;
* the thing it guards, the `EXCLUDED` disposition itself forced to `ROUTE`,
  kills **3**.
