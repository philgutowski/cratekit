## The hunts a green suite cannot see

- **An assertion whose expected value comes from the code under test.** Swept with
  an AST walk over every `assert` in `tests/test_adapter_listing.py`, not a grep.
  Five assertions have the module on both sides, all five in
  `test_every_declared_listing_shape_has_a_wrapper` and
  `test_every_shape_declares_the_rule_its_provider_can_actually_support`. Read
  individually, none is X equals X: each compares two separately maintained tables
  to each other, which is P4's property and is exactly what those tests are for.
  The one absence assertion, `SHORT_PAGE not in STOP_RULES.values()`, discriminates
  rather than observing an absence both trees produce, and rows `B1`, `B3`, `B4`
  and `B5` are the evidence, each killing by flipping a shape onto that rule.
- **A test that forbids a feature by naming the last implementation's symbols.**
  The absence assertion above names `StopRule.SHORT_PAGE`. A rename of that member
  breaks the test loudly with an `AttributeError` rather than passing quietly, so
  it forbids the rule and not one spelling of it.
- **Duplicate keys in a mapping several branches appended to.** AST walk over every
  dict literal in `listing.py`: none. The three shape tables were the risk, since
  they are keyed by the same four strings in three places, and
  `test_every_declared_listing_shape_has_a_wrapper` is what keeps them equal.
- **One symbol meaning two things in two modules.** `_shape` here returns a
  listing shape's pagination policy as call arguments; `core.naming._shape_for`
  returns a name template's shape. Different modules, unrelated meanings, similar
  name. Judged trivial and deliberately NOT renamed, because a cosmetic rename
  after the table was measured adds surface this table does not cover, for no
  correctness gain.
- **The first caller of an engine owns the engine's unreviewed failure paths.**
  This is the hunt that found something. `git grep get_tracks_count -- src`
  returned only this unit's own call, so U65 is the first and only caller of that
  endpoint. Reading its failure paths as its own: it is a plain request against
  the same API and session the walk is about to use, and it was NOT going through
  the retry ladder while every page after it was. A rate limit there would have
  failed the whole favourites read, a failure path that did not exist before this
  unit and would have been introduced BY the correctness fix. Fixed, with the two
  guards named above. The first attempt at the fix retried inside
  `_declared_count`, which used the real `time.sleep` and slept for three seconds
  in the test rather than honouring the caller's injected one; the ladder belongs
  in `paginate`, which is the only place that holds the caller's retry settings.
