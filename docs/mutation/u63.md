# U63 mutation table, author's

**Verdict.** Twenty five rows over the account adapter and its seam, all twenty
five killing on their subsets. Three were zero on the first pass and each asked
for a test, now added: M5, M6 and F7. Checked by hand, not by
`scripts/mutate.py`, because the driver's preflight is two full suite runs of
about 400 seconds each and cannot finish inside a relay task's ten minute
foreground call (R-329). Each row was applied alone from
`docs/mutation/u63-rows.toml`, its subset run with `PYTHONDONTWRITEBYTECODE=1`,
the collected count read off the summary line, and the file then rewritten from
`git show HEAD:<path>` and checked with `git diff --quiet`. Every restore matched.
The rows file's batch name is `u63-driver`, so an attended driver run writes
beside this file rather than over it.

**The author could not kill nothing, which is a claim about the author.** No
independent table was run. Kills on a subset are real kills; no zero was promoted
to a full suite, because none remained.

## The three zeros, and what killed them

- **M5.** No fake answered a track lookup with a different identifier, so the
  comparison guarded nothing the suite could reach.
  `test_a_reference_the_provider_answers_with_another_track_is_no_match` now does.
- **M6.** The name layer is covered by `classify_unavailable` for any class named
  `*NotFound`, and every fake used `ObjectNotFound`. The layer that layer does not
  cover is `InvalidISRC`, and
  `test_an_isrc_the_provider_will_not_accept_is_no_match_and_is_not_retried` drives
  it.
- **F7.** No fake wrapped its HTTP error. The provider client does, which is why
  `provider_session._rejected` walks the chain.
  `test_a_rejection_the_client_rewraps_is_still_read_as_a_rejected_session` now
  wraps one.
