# Mutation table: U104, `intake set` and `intake identify` fetch a mix URL

**The author's own table, 2026-09-19, on `relay/149` at 735b82f.** No
independent verifier ran. Every row reads as "the author could not make it
survive", and an independent table on this project has always found more.

**25 rows, 25 killed, no zero row.** Five null controls, one per batch, each
killed nothing. Every restore was verified against `git show HEAD:` by the
driver. The cap of 25 was reached and five considered rows were dropped and
NOT MEASURED; they are listed at the end with the reason each ranked below it.

## Why five batches and not one

`scripts/mutate.py` was run in the FOREGROUND, because the session that made
this table cannot wait on a background job. One invocation carries about 150
seconds of fixed cost, a full suite baseline and a promoted null control, and
the tool ceiling is 600 seconds, so a single 25 row run would have been killed
mid row with a mutation left in the source. Each batch is its own spec, its own
table and its own sidecar beside this file: `u104-a` to `u104-e`, with the rows
files that produced them. Every batch ran between 2:45 and 2:58.

Deaths were confirmed on a named subset, `tests/intake/test_set_fetch.py`, with
`tests/intake/test_workers.py` added for the rows in `intake/cli.py` and the
two second source test files for the row in `core/binary_refusal.py`. A death
on a subset is a real death. No row read zero, so nothing was promoted.

## The hunts a green suite cannot see

- **One symbol meaning two things.** Found and fixed after the table: the new
  `Recording` and `Fetched` classes shared their names with
  `modules/reports/duplicates.py` and `tagging/searchers.py`. They are
  `SetRecording` and `FetchedMix`. No row's old text names either, so the table
  stands.
- **The same shape one file over.** The case defect the review found in the
  library guard has thirteen siblings in `src`. Not driven, recorded in the
  ledger.
- **Expected values taken from the code under test.** Read by hand over the new
  file, not swept by an AST walk. One assertion compares the mix argv against
  U80's argv on purpose, to pin that only the template and the bound differ.
  The rest name literals.
- **The first caller of an engine.** `fallback.YtDlpFetcher` already had a
  caller, `acquire fallback-fetch`, so its failure paths were reviewed under
  U80. The one new dependence is that the mix download finds `--output` by
  position in U80's argv, and the argv test pins it.
